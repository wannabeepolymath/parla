## Formatting metric verdict: HOLDS (narrow scope)

The committed CLI quality gate does not directly enforce paragraph/newline fidelity or exact code-symbol preservation. Zero-edit and compare do preserve punctuation/case; the failing exit is based on WER. See the precise metric distinctions below. `Eval.normalize` collapses every whitespace run (Sources/ParlaCore/Eval.swift:5–6), and `Eval.werTokens` lowercases and splits punctuation/symbols (same file:36–40). `report` compares normalized strings and declares quality failure only above 20% WER (Sources/parla-eval/main.swift:192–195). Therefore `Hi Sam,\n\nThanks.` and `Hi Sam, Thanks.` are identical for the CLI's zero-edit measure and WER. A cleanup model can regress paragraph layout while keeping words and pass. Exact terminal flags/symbol changes may similarly escape WER. Opportunity: keep WER for recognition, add format-aware assertions for cleanup: paragraph boundaries, single-line destinations, code/identifier/symbol preservation, factual entities and quantities.

Strongest counterargument: the repo already has explicit unit tests for email insertion/paragraph survival and newline suppression, so it would be false to call formatting untested. Sources/ParlaCore/Cleanup.swift:73–86,136–148 request layout; Tests/ParlaCoreTests/DictationSessionTests.swift:86–91 prove email output survives delivery; :155–166 test single-line/browser chat policy. Tests/ParlaCoreTests/CleanupTests.swift:74–92 check browser hint and single-line prompt. These validate policy/delivery, not live model layout quality under the CLI gate. Findings require both facts.

URLs stay local; only category to provider (Cleanup.swift:6–8; TextRules.swift:68–80). Opportunity: user overrides, per-app style/model/dictionary, granular field handling. Strongest counterargument: generic delivery already handles unknown apps; missing category does not prove app incompatibility. 2. **HOLDS: ASR is concretely tied to WhisperTranscriber and whisper catalog; no engine abstraction/alternative in inspected shipping path.** Transcriber.swift:9; Dictation.swift:261–266,283–286; ModelCatalog.swift:41–54. Opportunity is evaluate an alternate engine before claiming speed/quality. Strongest counterargument: three whisper models and arbitrary model path already offer a real quality tradeoff; extra engines add packaging/lifecycle cost.
3. **HOLDS: current audio-worth-transcribing gate is duration/RMS rather than a speech detector.** TextRules.swift:106–114 explicitly says 'fixed thresholds, no VAD.' Opportunity: evaluate VAD/noise suppression against quiet speech/background noise. Strongest counterargument: this is intentionally a permissive near-digital-silence rejection, and streaming quiet-boundary handling already exists; a strict VAD risks clipping quiet speakers. No runtime hallucination rate measured here.
4. **HOLDS: Mac inline API-key settings persist in JSON; Android already has a credential vault.** Settings.swift:31,164–169 serializes settings; CleanupSettings.apiKey at :10–21. Android core/SettingsStore.kt:125 onward stores endpoint/provider-scoped encrypted credentials. Opportunity: Mac Keychain migration with env override. Strongest counterargument: local file + user API key is intentional BYOK behavior, and this audit did not establish incorrect filesystem permissions or credential disclosure. 5. **PARTIAL: insertion confirmation remains limited for opaque macOS apps.** Inserter.insert returns clipboard write/post result, not remote acceptance (Inserter.swift:22–37). Opportunity: optional bounded verification where AX permits and clearer attempted-vs-confirmed states for opaque clients; app qualification matrix. Strongest counterargument: retrying after an unverified paste can duplicate text; current destination checks and clipboard safety are meaningful. Android explicitly handles this better as attempted/unverified with no automatic retry.
6. **HOLDS: history retention is count-based, recovery retention is fixed days.** HistoryStore.cap=50 at History.swift:47; RecordingStore.retentionDays=7 at RecordingStore.swift:32, prune occurs on stash :101–115. ## Follow-up refutation: precise metric distinctions

- **HOLDS, paragraph/newline blind spot in reported quality measures:** `Eval.normalize` (Eval.swift:5–6) folds all whitespace, so both `Summary.zeroEdit` (parla-eval/main.swift:178) and WER miss paragraph-only changes. Whitespace folding is deliberate: `testCollapsesWhitespace` (Tests/ParlaCoreTests/EvalNormalizeTests.swift:38–39) explicitly requires it.
- **DOES-NOT-HOLD, broad claim that reported metrics ignore punctuation/case:** zero-edit preserves case and punctuation (`testCaseAndPunctuationPreserved`, EvalNormalizeTests.swift:41–43). `differences`/`CaseDelta.zeroFlip` keeps punctuation-only changes visible in compare (parla-eval/main.swift:248–260); self-check explicitly asserts a punctuation-only flip survives (:325). WER itself ignores punctuation/case, but not all reported measures do.
- **HOLDS, exit-code gate is WER-based:** `report` sets qualityFailed only for WER >20% (:192–195), so visible punctuation/case changes can remain successful exits. `compare` intentionally never exits 1 (:217–218). This is a policy limitation, not hidden total lack of punctuation awareness.
- Content: WER preserves lexical order/substitution/insertion/deletion but intentionally folds numeral forms, currency symbols to named currency, case and punctuation. Apostrophes inside words retained (Eval.swift:36–40). Distinct quantities/currencies tests guard false equivalence (EvalNormalizeTests.swift:103–123). Large semantic or symbol changes may still be low-WER; evaluating them requires entity/structure criteria, not claiming all content is unmeasured.
- Strongest argument against a 'formatting blind spot': unit tests explicitly protect delivery formatting, and zero-edit/compare already protect case and punctuation. The remaining narrow opportunity is paragraph-sensitive model-result metrics and chosen quality gates, especially for email/list formatting; avoid overbroad wording.
