## R1 — Native preparation and failure ownership (separate neutral audit)

**Narrow conclusion: HOLDS.** Whispaste represents a wired, best-effort restart-time escape from repeated *unfinished GPU model load/warmup attempts*. Parla has caught-error handling and preparation/retention safeguards, but no equivalent persisted attempt streak or selectable CPU recovery in the inspected native model path. This is not proof Parla experiences a crash loop, nor proof Whispaste can reliably identify/fix every native death.

**Concrete chain:** `GpuLoadCrashGuard.markAttempt` writes a synchronous marker before load ([lib/services/stt/whisper/gpu_load_crash_guard.dart:98–120](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/stt/whisper/gpu_load_crash_guard.dart#L98-L120)). `_start` sets it only for a requested non-CPU backend, clears it after a caught load exception, retries the load once on a CPU engine, and otherwise retains it through warmup; successful warmup resets streak ([lib/services/stt/stt_server_state_notifier.dart:1429–1524](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/stt/stt_server_state_notifier.dart#L1429-L1524)). `main._runApp` awaits recovery before runApp ([lib/main.dart:320–329](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/main.dart#L320-L329)). `recoverFromGpuLoadCrash` consumes the marker, records strikes, silently retries GPU after one, disables GPU at two after settings update, and arms user notice; CUDA-tagged attempts disable only the CUDA pack first ([lib/services/stt/whisper/gpu_load_crash_guard.dart:219–219](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/stt/whisper/gpu_load_crash_guard.dart#L219-L219), [lib/services/stt/whisper/gpu_load_crash_guard.dart:240–337](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/stt/whisper/gpu_load_crash_guard.dart#L240-L337)). Therefore “marker/fallback is merely an unused utility” does not survive caller inspection.

**Disconfirming evidence and reliability limits:** marker I/O catches and logs failures without blocking native load; writes omit explicit flush/fsync, so not a durable power-loss protocol. Force quit/reboot or an unrelated fault in the marked interval can count as GPU failure; no crash reason, model/backend revision or process ownership is encoded beyond timestamp/CUDA prefix. Failures after warmup are outside this restart marker's coverage. Clear/delete failures may leave a stale marker. CPU loading can itself fail or die. Settings update is not transactional with marker/streak: SettingsNotifier.updateSettings changes in-memory AsyncData **before** awaited secure-store/SQLite persistence ([lib/core/config/settings_provider.dart:1077–1090](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/core/config/settings_provider.dart#L1077-L1090)). On real persistence failure the current process can already see CPU-off/CUDA-off while the saved setting has not changed; the guard catch comments/test fake do not establish rollback. So do not repeat the comment's categorical “GPU will be attempted again this launch” as observed behavior. The escalation retains the strike count on failed persistence, but clearing the in-flight marker does not itself schedule another save. No reliable guaranteed recovery under storage failure claimed.

**Parla equivalent protections and constraints:** `WhisperTranscriber.init` calls native init with default GPU/flash parameters and throws only if it returns nil (Sources/ParlaCore/Transcriber.swift:41–53). `decode` returns nil for native nonzero/cooperative abort, separate from empty successful speech (same:58–63,127–159). A process-killing native fault cannot be caught by try?/Swift error handling. `AppDelegate.loadModel` validates owned artifacts before native init, assigns modelReady only on returned context, and serializes/preempts throwaway warmup (Sources/Parla/main.swift:328–367); warmup result is ignored, so readiness is not proof warmup succeeded. `activeTranscriber` retries a failed reload using an in-memory lastGoodModelPath (main.swift:378–385), not a persisted backend fallback. Idle unload is recording-safe and serialized (main.swift:389–410; Transcriber.swift:209–232). RecordingStore's seven-day failure-audio stash (RecordingStore.swift:12–32) recovers audio, not a GPU selection/startup crash. `Settings` fields (Settings.swift:25–70) have no acceleration/strike settings; no marker around native preparation was found in loadModel or Transcriber. No native crash was induced.
