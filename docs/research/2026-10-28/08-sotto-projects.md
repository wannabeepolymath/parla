## S1 — microphone signal self-test: HOLDS, narrow diagnostic extension

Candidate NEW-S1 (M, roughly 3–5 days), adjacent to B11 diagnostic export but a different interactive capability. `MicrophoneTest::spawn_workers` reads the selected recorder's level, discards its accumulation, emits display levels, and optionally streams correctly rate-tagged audio to a listening monitor. A silence watcher checks whether any real signal appeared; it explicitly says silence alone does not prove permission denial. Frontend subscribes, plays chunks and stops on unmount. This can help a user distinguish wrong input, low signal and an unpleasant sounding microphone before ASR. It does NOT implement a calibrated clipping/noise/SNR classifier.


Evidence: [desktop/src-tauri/src/mic_test.rs:195](https://github.com/stofll/Sotto/blob/26a1da6cc81811c12c85e8b0d1e336ff052d7bad/desktop/src-tauri/src/mic_test.rs#L195-L295); [desktop/src/pages/settings/MicrophoneSection.tsx:180](https://github.com/stofll/Sotto/blob/26a1da6cc81811c12c85e8b0d1e336ff052d7bad/desktop/src/pages/settings/MicrophoneSection.tsx#L180-L245); command registration [desktop/src-tauri/src/lib.rs:1587](https://github.com/stofll/Sotto/blob/26a1da6cc81811c12c85e8b0d1e336ff052d7bad/desktop/src-tauri/src/lib.rs#L1587-L1588).


Parla equivalents/counterevidence: `Settings.inputDeviceUID` (Sources/ParlaCore/Settings.swift:61–63), input picker (Sources/Parla/Hub/HubPages.swift:95), `HUD.push` and waveform (Sources/Parla/HUD.swift:337,491–515), and sandboxed `tryout`/`tryoutStart` (Sources/Parla/Hub/Onboarding.swift:208–290) already expose mic selection, signal display and an ASR test with no external insertion. Thus “no microphone test” DOES-NOT-HOLD. The narrow difference is an ASR-independent selected-device listening monitor plus explicit signal/no-signal diagnosis. Strongest counterargument: onboarding already answers whether dictation works; echo monitoring adds feedback-loop risk and maintenance with unmeasured value. Deliberate boundary: Parla tryout requires a loaded model and is isolated from Inserter; Sotto's silence message is deliberately non-diagnostic about permission. Acceptance: test without a loaded ASR model; unplug/change device, no signal, low speech and 44.1/48kHz; bounded buffers; stop on close; never insert/save test audio; explicit headphones/monitor action; don't label peak-hold as clipping detection.

## S2 — preview/final model split: HOLDS as an experiment, no demonstrated speed win

Candidate NEW-S2 (M–L spike, about 1–2 weeks), adjacent to B16 engine seam and B30 long cleanup, neither of which specifies two ASR models. Tomoima constructs separate main and streaming transcribers, warms the streaming model lazily, emits drafts with it, and at stop optionally decodes collected speech audio with the main model. Collection stops after 120 seconds of speech; refinement exceptions or output below 70% of preview text length fall back to joined preview segments. Menu wiring exposes both choices. This is concrete preview/final strategy, not proof its final text is more accurate.


Evidence: [src/sotto/pipeline.py:76](https://github.com/tomoima525/sotto/blob/b2bbde271fff414256b1c1781f872af690548395/src/sotto/pipeline.py#L76-L97); [src/sotto/pipeline.py:250](https://github.com/tomoima525/sotto/blob/b2bbde271fff414256b1c1781f872af690548395/src/sotto/pipeline.py#L250-L310); final caller [src/sotto/pipeline.py:327](https://github.com/tomoima525/sotto/blob/b2bbde271fff414256b1c1781f872af690548395/src/sotto/pipeline.py#L327-L350); menus [src/sotto/app.py:80](https://github.com/tomoima525/sotto/blob/b2bbde271fff414256b1c1781f872af690548395/src/sotto/app.py#L80-L92).


Parla: `Settings.streamPreviewEnabled` (Settings.swift:55–59) already offers HUD-only previews; `Dictation.stream(transcriber:gen:dictionary:preview:)` (Sources/Parla/Dictation.swift:462,509–529) and `finish` pipeline (same file:261–286) use the same WhisperTranscriber. Windowed finalization already avoids decoding the full utterance repeatedly. Strongest counterargument: a second resident model increases memory/load work and a whole-session final decode can increase stop latency; the 70% guard is not semantic correctness, and speech-only concatenation changes timing context. Deliberate policy: Parla previews default off to avoid extra passes; no preview is inserted/stored; Sotto caps refinement retention. Acceptance: held-out Hindi/English switching and quiet speech; paired final quality, time-to-preview, stop latency, cold/warm memory; fail/cancel/model switch; no speculative preview insertion; long-session fallback preserves text. Promote only with measured benefit.

## S3 — accidental cancellation recovery: HOLDS, new product experiment

Candidate NEW-S3 (M, roughly 3–5 days); related to B46 failed-audio recovery, but cancellation is an intentional discard, and B24 concerns undoing delivered text. Psancheti retains cancelled capture in RAM, shows a timed Undo, queues retained audio on Undo, and drops the reference on expiry or when no overlay exists. Config defaults the window to three seconds. Actual overlay callbacks are wired to undo and expiry.


Evidence: [sotto/app.py:133](https://github.com/psancheti6666/sotto/blob/bf7510798482438e9e9373643591706c69e05b91/sotto/app.py#L133-L164); [sotto/app.py:381](https://github.com/psancheti6666/sotto/blob/bf7510798482438e9e9373643591706c69e05b91/sotto/app.py#L381-L394); [sotto/config.py:101](https://github.com/psancheti6666/sotto/blob/bf7510798482438e9e9373643591706c69e05b91/sotto/config.py#L101).


Parla: `DictationSession.send` cancel branch (Sources/ParlaCore/DictationSession.swift:359–386) deliberately bumps generation, stops capture with discard=true and discards the stream window; no undo buffer is exposed. Existing RecordingStore crash/failed-ASR recovery is an alternate workflow, not cancellation recovery. Strongest counterargument: Cancel should mean discard immediately, especially for sensitive speech; retaining cancelled audio is a privacy/product change, not a correctness fix. Sotto's `_process_audio` later injects into current focus (app.py:180–195) without preserving a field/selection identity in this queue; do not copy that delivery behavior. Acceptance: explicit opt-in and visible expiry; no disk write; expiry/new recording/quit clear buffer; secure fields excluded; undo returns text/copy when original destination no longer matches; never silently paste into a later field; test expiry/undo and repeated cancel races. Source tests inspected covered hotkey cancel but did not establish undo-session end-to-end qualification.

## Things checked that were fine / rejected patterns

- All four root licenses are MIT; source licenses do not automatically establish licenses of external model weights.
