## M1 — Optional microphone route comparison/calibration (NEW candidate)

**HOLDS, narrow:** the inspected Android Parla capture has no user-guided route calibration/quality comparison; Outspoke has an end-to-end implemented path.

**Mechanism and actual caller:** `MicCalibrationViewModel.startCalibration` loops microphones, records a three-second reference per microphone, calls `MicScorer.score`, and persists the highest positive score [ViewModel:85–115,129](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/settings/preferences/MicCalibrationViewModel.kt#L85-L132). `MicScorer.score` ranks high-frequency energy fraction plus percentile RMS SNR [MicCalibration:73–95](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/audio/MicCalibration.kt#L73-L95). The capture path really reads that preference and calls `setPreferredDevice` [AudioCaptureManager.applyPreferredMic:272–285](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/audio/AudioCaptureManager.kt#L267-L285), invoked before recording [:170–176](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/audio/AudioCaptureManager.kt#L170-L176). This is more than a settings mockup.

**Parla comparison:** `AudioCapture.start`, `android/app/src/main/java/com/parla/android/speech/AudioCapture.kt:26–50`, selects VOICE_RECOGNITION, 16 kHz mono, with no preferred input setting. `capture:104–118` already detects route changes and refuses to mix routes. Desktop already has device selection (`Sources/ParlaCore/AudioRecorder.swift:70–103`) and `Settings.inputDeviceUID`; do not generalize this into missing microphone selection across Parla.

**Deliberate boundaries/tests:** Outspoke `listInputMics:158–165` prefers built-in inputs and uses all inputs only if none are built-in; stored Android device ID can disappear. Capture selection is gated to API 29+, with missing-device fallback. Calibration recording and production recording are not an assurance of identical Android processing. `MicScorerTest.silenceScoresZero/shortClipScoresZero/highFrequencyClipScoresHigherThanLowFrequencyClip` exercise synthetic scoring [tests:35–73](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/test/kotlin/dev/brgr/outspoke/audio/MicScorerTest.kt#L35-L73), not ASR quality or routing success. The code ignores the Boolean return from `setPreferredDevice`; a production diagnostic should display the actual routed input.

**Strongest counterargument:** spectral/SNR proxies may reward hiss and cannot establish better recognition; Android may expose only one logical microphone or ignore a preferred route. Parla's system-selected VOICE_RECOGNITION route is a reasonable simple default. No evidence here warrants automatic winner selection or an accuracy claim.

**Effort:** M for optional route picker, recording comparison and route diagnostics; calibration ranking plus physical-device qualification may make this L. **Acceptance:** permission revocation, cancellation, unplug/reboot/stale IDs, Bluetooth and actual routed-device mismatch; clean/quiet/noisy clips, no retained calibration audio by default; same utterances decoded with paired human references before recommending a winner. Preserve current route-change stop behavior. **Backlog:** new candidate, dependent on B02/B08-style physical qualification; distinct from model/language B12 and padded VAD B17.

## M2 — User-chosen cursor-word correction candidates (B29 extension/reinforcement)

**HOLDS, narrow:** Outspoke exposes an explicit word replacement surface backed by acoustic alternatives or phonetic/edit-distance dictionary candidates. Current Parla dictionary learning is a different implemented feature.

**Retained-state boundary:** `AcousticCandidateCache` is synchronized, case-insensitive and holds 200 distinct word keys; replacement overwrites an earlier occurrence's alternatives [cache:36–78](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/inference/AcousticCandidates.kt#L36-L78). Its clear occurs after the non-streaming fallback branch in `InferenceRepository.transcribe`, so do not claim all engine paths demonstrably clear it on entry [repository:1339–1357](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/inference/InferenceRepository.kt#L1339-L1357). Session/occurrence identity is a stronger adoption design than a word-only key.

**Parla:** `Sources/ParlaCore/DictionaryLearner.swift:89,146,161` produces proposals from later user correction; `Sources/Parla/Dictation.swift:667–678` watches a field and adds a proposal for Hub confirmation. Android `core/TextRules.kt:8–15,82–90` supplies dictionary/snippet behavior; `input/DictationPanel.kt` and `DictationManager.retryCleanup/useOriginal:128–138` give raw/retry controls. None of these is an acoustic cursor-word candidate picker. This is not a claim that Parla lacks dictionary learning or manual editing.

**Deliberate/tests:** enabled-language filtering, empty set no-op, no suggestion delivery during active dictation/dismissed bar [VM:170–175](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/ui/keyboard/KeyboardViewModel.kt#L170-L175). Provider tests cover contextual acoustic rescore, lookup, dictionary fallback and disabled languages [tests:133–206](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/test/kotlin/dev/brgr/outspoke/ime/WordSuggestionProviderTest.kt#L133-L206); cache tests cover eviction/clear/concurrency [tests:48–98](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/test/kotlin/dev/brgr/outspoke/inference/AcousticCandidateCacheTest.kt#L48-L98).

**Strongest counterargument:** extracting ASR alternatives requires a new output seam; Whisper currently returns strings. Lexicon filtering can exclude exactly the rare names users care about, word-only cache conflates repeated words, and async provider delivery has no visible request token in `getSuggestions`. Existing dictionary hints and user edits may be enough. No candidate recall/precision measured here.

**Effort:** M dictionary-only explicit picker, L acoustic occurrence-linked extension with B16 seam. **Acceptance:** ties, repeated same word in different contexts, stale cursor/field/session changes, surrogate pairs, selection changes, password fields, no auto replacement, disabled languages, bounded cache cleared on all engine starts; report candidate recall and false suggestions on B02 references. **Backlog:** fold into B29 as a safer user-selected experiment; B28 enrollment remains separate. Do not create a duplicate generic acoustic-repair row.

## M3 — VAD, stop/drain and partial/final lifecycle (B17/B16/B30 reinforcement)

**Observed Outspoke mechanism:** `SileroVadFilter` carries h/c RNN state, onset/pre-roll/hangover smoothing; `flush` clears smoothing and h/c [filter:115–178](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/audio/SileroVadFilter.kt#L115-L178). `AudioCaptureManager.startCapture` passes frames through VAD; on normal stop, drains hardware nonblocking and feeds a bounded number of silence frames through VAD before completion [capture:208–239](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/audio/AudioCaptureManager.kt#L208-L239). **Parla boundaries already implemented:** desktop `Sources/Parla/Dictation.swift:84–92,448–570` already shadow-streams, serializes access to nonreentrant whisper context, gates writes by generation and passes confirmed prefix to finalization. `discardStreamWindow:76–82` clears on the task chain and `stream:556–562` explicitly writes nil to avoid inheriting prior text. Android `DictationManager.stop:84–112` captures then runs whole-utterance recognition; `AudioCapture.finish/capture:86–137` joins capture, releases the mic in finally and handles route/silence interruptions. `DictationManager.start:63–75/cancel:157–170` owns generation and time cap. Android streaming insertion would be new scope; desktop streaming is not absent.

**Deliberate/tests:** Outspoke `TextInjector.commitFinal` preserves a longer composing span only for a strictly shorter trailing subset, while allowing same-length refinements [injector:533–618](https://github.com/minburg/outspoke/blob/2b676cebb52f314fe3962ab6ae2a6b041381cdcb/app/src/main/kotlin/outspoke/ime/TextInjector.kt#L533-L618). **Strongest counterargument/rejected adoption:** VAD can reject quiet short speech; upstream's missing-session fallback uses RMS 0.01 (`SileroVadFilter.process:107–110`), not evidence it is right for Parla. Incremental text is difficult to retract safely; `TextInjector.commitFinal:736 onward` explicitly prefers appending full final after failed alignment, accepting potential duplication. Preserve Parla's destination identity/no-retry policy. No source inspection proves Parla currently loses a final phoneme: drain is an experiment/acceptance target, not a confirmed defect.

**Effort:** M–L B17 spike; L Android partial composing pilot with engine seam. **Acceptance:** stop vs cancel, no post-cancel delivery, quiet one-word onsets/endings, drain bounded under continuous capture, many utterance boundaries, exact-once final, same-length punctuation refinement, truncated final, rejected composition, cursor/field edits and stale sessions. Compare ASR and delivery separately, retain permissive baseline. **Backlog:** reinforce B17/B16; B30 only covers incremental cleanup, so Android live-composition work should be an explicitly scoped sub-experiment rather than claiming B30 already ships it.

Thus file-tail handling must not be represented as proof of identical live finalization. Original phone-whisper merely feeds and offline-decodes [original:15–21](https://github.com/kafkasl/phone-whisper/blob/e6518cda437ed2c266f36cf476db857fa2690d87/app/src/main/kotlin/com/kafkasl/phonewhisper/LocalTranscriber.kt#L15-L21); model wrapper lineage is counted once.

**Parla:** Android `speech/WhisperEngine.transcribe:17–49` takes FloatArray from microphone capture; `DictationManager.stop:84–112` supplies captured samples. **Strongest counterargument/rejected patterns:** this is an adjacent workflow, not a core dictation defect. **Effort:** L existing B41. **Acceptance additions:** URI permission lifetime, truncated/unsupported/large files, G.711 and interleaved formats, output format changes/offsets, input-EOS with pending nonempty output, EOS timeout, cancellation during decode and ASR, bounded memory, finally release, last-word paired fixtures. **Backlog:** reinforce B41; no new import row.

## R2 — Single neutral input-trigger comparison

**Verdict: HOLDS for the narrow conclusion:** OpenSuperWhisper has wired configurable extra mouse-button recording triggers; current Parla's native recording trigger schema/event tap is keyboard-only. This is an optional input modality distinction, not evidence that Parla lacks configurable hotkeys, push-to-talk, hands-free or cancellation.

- Parla `KeyChord` is physical UInt16 keyboard keyCode plus exact modifier set (`Sources/ParlaCore/Hotkey.swift:11–56`); `HotkeyBindings:165–228` rebinds PTT modifier, hands-free chord, paste-last and scratchpad. `Settings.hotkeys`, `Sources/ParlaCore/Settings.swift:63–65,90`, persists it. ### Cancellation and recovery boundaries

Parla `HotkeyMonitor.keyDown:450–485`: Escape while capture monitor session is active cancels and is swallowed; another key during PTT cancels and passes through; typing during hands-free passes through except bare/Shift latch key or Return stopping it; Esc while idle emits dismiss and passes through. Modified Esc cancellation is explicit policy, including once swallowing Force Quit chord. `main.swift:237–255` confirms routing. `DictationSession.cancelRequested`, `Sources/ParlaCore/DictationSession.swift:359 onward`, is guarded to an actual capture; do not equate this with a universal cancel during post-stop ASR/cleanup. After monitor returns idle, Esc only reaches `hud.dismiss`. The HUD has its own cancel event, whose reducer boundary still matters.

Upstream Escape is registered separately (`ShortcutManager.setupKeyboardShortcuts:81–86`) and routes to `IndicatorWindowManager.requestCancel:253–257`, then view-model cancellation. `IndicatorViewModel.cancelRecording` invalidates decoding session, cancels Swift/native operations during decoding [indicator:375–398](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/Indicator/IndicatorWindow.swift#L375-L398). Cancellation can be mediated by confirmation policy; not every Esc means immediate discard. Existing regression explicitly reaches decoding without an active recording reference [test:168–186](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisperTests/TranscriptionCancellationTests.swift#L168-L186). This is a second routing boundary to preserve in any trigger design, not a proposed extra finding/ticket in this comparison.

Parla is stronger in observed trigger recovery machinery: `HotkeyMonitor.reconcile:373–384` synthesizes missed release from physical state, watchdog checks tap liveness, and `endSession:387–399` unlatches recorder self-end. `Dictation.swift:76–92,524–570` serializes stream finalization and generation-checks stale writes. Upstream monitor re-enables a disabled tap (`reenableTap:133–137`) but `stop:120–129` only clears pressed state, and no physical mouse release reconciliation is present in this class. A safe adoption must not simply copy the monitor and lose Parla's liveness behavior. Queued async monitor callbacks capture self and read closures at delivery time; settings reconfiguration needs generation-bound dispatch tests. These are source boundaries requiring tests, not demonstrated lost-release incidents.

### Strongest argument against the verdict

Parla already supports a broad configurable keyboard path and external remapping can give a mouse user equivalent day-to-day interaction. Upstream's new trigger adds event suppression, permission, lost-release and reconfiguration complexity. Source availability does not prove the mouse path works on real hardware or is safer. Therefore a broad claim that upstream offers better hotkeys/cancellation DOES-NOT-HOLD; the native extra-button modality distinction is the supported narrow result.

### Deliberate policy and tests (separate)

Parla explicitly reserves Shift for command mode and Esc for cancel (`HotkeyBindings.problem:196–207`), uses exact modifiers to avoid stealing other chords, and allows mouse destination selection while capturing (`DictationSession.swift:528` comment). Tests cover cancel/pass-through `HotkeyTests.testKeypressWhileHeldCancelsAndSwallowsUp:74`, missed release `:94`, re-press splitting `:132`, self-ended hands-free `:173`, hands-free typing `:276`, Esc `:306,390,398`, rebinding validation `:625–650`. Existing tests are strong counterevidence against treating triggers as generally absent or untested.

Upstream mouse tests cover enum roundtrip, invalid values and button mapping [tests:1740–1765](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisperTests/OpenSuperWhisperTests.swift#L1740-L1765). Permission reconfiguration is tested [TriggerPermissionTests:7](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisperTests/TriggerPermissionTests.swift#L7); session controller tests assert another trigger stops original owner once [RecordingSessionTests:6](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisperTests/RecordingSessionTests.swift#L6).
