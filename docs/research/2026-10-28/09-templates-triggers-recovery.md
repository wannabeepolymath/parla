# WhisPaste and OpenSuperWhisper: additional source evidence

Research date: 2026-10-28. Static source only; no builds, installs, models or target-app testing. “Additional” means outside the first 20 audited repositories, not necessarily newly launched. WhisPaste pinned `594e7272700e2d3e827512c7e876b26eef6f1ddf` (MIT); Starmel/OpenSuperWhisper pinned default branch develop `c8e6fe79d6851078940f459ab7dbc8ee39e2a97d` (MIT). GitHub push time and selected commit time differ; the manifest records both discovery and commit dates rather than presenting push activity as release freshness.

## R01 — Guided, named-field voice templates and a snippet picker

WhisPaste has a real session layer above recording: [InteractiveSnippetController](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/snippets/interactive_snippet_controller.dart#L113-L188) starts with a briefing, announces each field, records the field and collects the results. Its [completion path](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/snippets/interactive_snippet_controller.dart#L296-L329) clears the session and composes a final document. The [composer](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/snippets/interactive_snippet_composer.dart#L26-L51) places named fields into user-authored placeholders; [editor validation](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/features/snippets/snippets_page.dart#L690-L715) requires field names/placeholders. [Orchestrator wiring](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/recording_orchestrator.dart#L2078-L2141) captures a target before recording and creates one final history entry, avoiding replacement processing a second time over the completed template. The [picker dispatch](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/snippet_picker/snippet_picker_dispatch.dart#L40-L85) is shared by voice trigger and hotkey.

Parla's Settings.snippets is `[String:String]` (Sources/ParlaCore/Settings.swift:27); Pipeline.snippetExpansion matches an entire utterance (Pipeline.swift:53), while inline triggers are intentionally left to cleanup. These are useful existing features, but not a guided multi-recording form. A candidate feature would collect “title / reproduction / expected result” or “recipient / topic / next step” and preview a completed document before a single guarded paste. L, after ordinary workflow/profile foundations; useful as an extension of snippets, not a new meeting workspace.

Counterargument: most users can dictate the whole text or use a static snippet, and a multi-step flow adds hotkey/state/focus complexity. Do not assume upstream target priming proves safe final insertion. Preserve Parla's destination continuity validation; offer copy when it changed. Do not recursively substitute placeholder-looking dictated values. Acceptance: repeated/empty/Unicode fields, literal placeholder content, cancel during announce/decode, superseded sequence, target edit/switch, one final history record and zero partial external insertions. Independent comparison R3 confirms the guided workflow and narrows destination continuity to PARTIAL; see [the detailed check](08-sotto-projects.md#r3--neutral-snippet-data-model-and-session-flow-comparison).

## R02 — Optional mouse-button push-to-talk

OpenSuperWhisper's [MouseButtonMonitor](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/MouseButtonMonitor.swift#L5-L46) exposes middle and extra buttons. Its [event tap](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/MouseButtonMonitor.swift#L64-L119) consumes only the configured button and re-enables disabled taps; [down/up handling](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/MouseButtonMonitor.swift#L140-L166) debounces transitions. [ShortcutManager wiring](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/ShortcutManager.swift#L95-L139) connects this to recording and makes keyboard/modifier/mouse trigger modes mutually exclusive.

Parla already has configurable keyboard chords, modifier-only triggers and hands-free behavior. KeyChord/HotkeyBindings store keyboard keycodes (Hotkey.swift:11,165); pointer events currently participate in cancellation, not a configured mouse-recording action. Candidate: opt-in side/middle-button PTT feeding the existing reducer rather than a second recording state machine. M plus device qualification.

Counterargument: consuming Back/Forward changes familiar mouse behavior, event-tap recovery may leave an unknown pressed state, and ordinary keyboard PTT already works. Do not copy the upstream priority policy unless it suits Parla. Acceptance: configured/unconfigured buttons, no browser navigation from the bound gesture, lost release, tap disable, mouse unplug, permission change, secure input and starting/stopping inside a different target. Independent comparison R2 confirms the narrow native-trigger distinction and rejects a broader hotkey-superiority claim; see [the trigger audit](07-additional-android.md#r2--single-neutral-input-trigger-comparison).

## R03 — Bounded recovery from repeated native model-preparation crashes

WhisPaste persists a GPU-load attempt, counts consecutive interrupted loads, treats an optional CUDA pack separately, and notifies after persisted recovery. [Marker and streak code](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/stt/whisper/gpu_load_crash_guard.dart#L68-L219); [startup recovery](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/stt/whisper/gpu_load_crash_guard.dart#L240-L336). Crucially, [caller wiring](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/stt/stt_server_state_notifier.dart#L1429-L1507) keeps the attempt marker through first inference, not only weight loading. [main startup](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/main.dart#L320-L329) performs recovery before normal startup. Pure I/O [tests](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/test/services/stt/whisper/gpu_load_crash_guard_test.dart) cover markers and thresholds; source existence is not a real GPU-crash qualification result.

Parla verifies model bytes, handles a failed Whisper initialization returning nil, supports idle reload and warms the model (Transcriber.swift:41; main.swift:328–368). Those are not absent. Candidate improvement: a model/backend/version-scoped interrupted-preparation marker and an explicit reversible recovery choice if repeated process death prevents opening settings. M; strongest relevance when adding alternate/native backends. There is no evidence here of Parla users actually experiencing such a crash loop.

Counterargument: forced quit or power failure can leave a marker without a GPU fault. Do not copy CUDA/Vulkan policies onto Metal or disable acceleration after one interruption. Retain verified models, bounded counters and an explicit retry/reset. Acceptance: orderly failure clears marker, native-death simulation recovers on next launch, warmup remains covered, settings writes fail safely, artifact/backend upgrades scope markers, and CPU fallback is offered only if actually supported. Independent comparison R1 confirms wired best-effort restart recovery, with persistence and false-attribution limitations; see [the lifecycle audit](06-additional-desktop.md#r1--native-preparation-and-failure-ownership-separate-neutral-audit).

## R04 — Layout-aware shortcut display, with canonical serialization preserved

OpenSuperWhisper's [KeyboardLayoutProvider](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/Utils/KeyboardLayoutProvider.swift#L38-L94) resolves key labels from the active layout with UCKeyTranslate and detects keyboard geometry. Its `resolveInfo` deliberately returns nil for non-ANSI geometry; do not call it complete ISO/JIS support. It is [used by onboarding](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/Onboarding/OnboardingView.swift#L355-L359), rather than proof every shortcut UI is localized.

Parla explicitly uses US-ANSI physical-position labels both for display and settings serialization (Hotkey.swift:87–112), while matching physical keycodes. Candidate: a separate localized display formatter; keep physical matching and stable canonical settings names. S–M. Counterargument: users may intentionally prefer stable positional labels, and changing the canonical table would break readable settings/imports. Acceptance: QWERTY/AZERTY/QWERTZ, layout changes while the Hub is open, explicit ISO/JIS fallback, named function/modifier keys, and identical persisted chord before/after display changes. This is a display improvement, not a claim current key matching is broken.

## R05 — Language-specialized models and selection-aware language policy (reinforces B12/B16/B31)

OpenSuperWhisper's [catalog](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/Settings.swift#L549-L615) includes an ivrit.ai Hebrew-tuned Whisper model and preferred language metadata. Its [selection action](https://github.com/Starmel/OpenSuperWhisper/blob/c8e6fe79d6851078940f459ab7dbc8ee39e2a97d/OpenSuperWhisper/Settings.swift#L58-L69) applies language preference on explicit user selection, not restore/init. This is a useful concrete pattern for a capability-aware model catalog.

Parla already has multilingual desktop models, pinned language and a custom model path. The opportunity is a curated, verified model/language compatibility catalog with measured cohort quality; do not add “desktop multilingual” as a new gap or infer fine-tune superiority from a name. Preserve exact bytes/hash checks and make model-specific language switches visible and reversible. New Indic, Hebrew or other regional models require their own artifact/model-term and hardware review; this report establishes no quality result. No additional backlog row is needed beyond the existing engine/catalog initiatives and new language policy evidence.

## R06 — Automation API design reference, still deferred behind native automation

WhisPaste's [HTTP transport](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/automation_api/automation_api_server.dart#L24-L62) binds loopback. Its [Host guard](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/automation_api/automation_api_host_guard.dart#L15-L74) and [bearer authentication](https://github.com/whispaste/whispaste/blob/594e7272700e2d3e827512c7e876b26eef6f1ddf/lib/services/automation_api/automation_api_auth_middleware.dart#L21-L59) are distinct controls; the expected token is read per request. Tests exist for transport, token store, routing and middleware. This is a reference mechanism, not an API security audit or proof that all adjacent endpoints satisfy every requirement.

The first report's B19/W06 already favors native Shortcuts before a server. Keep that ordering. If an actual script/agent integration later needs a local API, preserve explicit enable/revoke, small routes, current-session ownership and reviewed delivery. “Localhost” alone is not an authorization contract. No new feature row or hosted service is warranted merely because this competitor has a server.

## Checked-fine and rejected patterns

- No basic dictionary/snippet/selection-transform/history/warmup/microphone-selection gap was inferred; Parla already implements them.
- A UI or benchmark fixture in a source tree is not a measured result from this research.
- A mouse-button monitor is a trigger extension, not evidence of general accessibility superiority.
- Do not copy sequential placeholder substitution into a design that requires literal opaque field values; templates should not re-interpret dictated content.
- Preserve Parla's full clipboard representations, secure-input guards and destination identity checks when borrowing workflows.
- A larger model catalog, an overlay constructor or additional telemetry is not automatically higher user value than daily cleanup and delivery qualification.
