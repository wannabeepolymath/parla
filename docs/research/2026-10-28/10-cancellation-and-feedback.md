# Cancellation and session-ownership blind audit

Read-only source review, 2026-10-28. Reviewed current `Sources/ParlaCore/Hotkey.swift`, `DictationSession.swift`, `Sources/Parla/main.swift`, `Dictation.swift`, `HUD.swift`, and relevant session, hotkey, streaming, destination, clipboard and recording-store tests. Followed delivery into `Inserter`, `InsertionDestination` and `ClipboardDelivery`. No subagents, code edits, builds, installs, model execution or runtime tests. Test references below describe existing assertions, not freshly executed results. Paths are relative to `/Users/daksh/mySpace/code/wisper`. Competitor comparison was unnecessary to establish these contracts.

## Deliberate contracts

- **Cancel means abort active capture.** `DictationSession.handle(.cancelRequested)` at `Sources/ParlaCore/DictationSession.swift:359` requires `isCapturing`, discards audio, bumps the generation, clears the typed ledger, queues stream-window disposal, and chooses silent hide versus cancellation feedback. A short tap never queues final recognition. `testShortTapDiscardsSilentlyAndNeverTranscribes` (`Tests/ParlaCoreTests/DictationSessionTests.swift:501`) and `testCancelIsIgnoredOnceTheCaptureIsDone` (`:541`) explicitly assert this boundary.
- **Esc after release is dismissal, not cancellation.** `HotkeyMonitor.keyDown` (`Sources/ParlaCore/Hotkey.swift:455`, `:485`) cancels a live hotkey session but otherwise emits `.dismiss` and passes Esc through. `AppDelegate` routes dismissal directly to the HUD (`Sources/Parla/main.swift:254`). `HUD.dismiss` (`Sources/Parla/HUD.swift:341`) intentionally leaves recognition/formatting visible, explaining that hiding it would falsely imply cancellation. Modified Esc during capture is also deliberately swallowed (`Hotkey.swift:450`).
- **New capture wins foreground ownership; old work may finish.** Session settings and command selection travel by value (`DictationSession.Session`, `Sources/ParlaCore/DictationSession.swift:94`). New starts consume a generation; refused commands do not (`handle`, `:290`, `:303`). Recognition, streaming and cleanup share a serialized `processTask` chain (`Sources/Parla/Dictation.swift:84`, `:102`, `:359`), preserving the non-reentrant recognizer and window handoff. Stale results may still enter history when enabled.
- **Delivery differs by path.** With cleanup configured, production sets `deferInsertionUntilClean: true` (`AppDelegate.finish`, `Sources/Parla/Dictation.swift:330`) and inserts once after cleanup. Destination identity is sampled before that await and checked afterwards (`:339`, `:365`); newer generations withhold insertion. Without cleanup, older raw transcripts intentionally still land (`DictationSession.transcribed`, `Sources/ParlaCore/DictationSession.swift:456`), explicitly tested by `testStaleTranscriptStillLandsButNeverTouchesTheNewerSession` (`Tests/ParlaCoreTests/DictationSessionTests.swift:710`). That test protects state/menu/unload, not every HUD effect.

## Narrow conclusions and improvements

**HOLDS — some old completion paths can overwrite or hide a newer recording HUD.** Start/release session A, start session B while A is processing, then let A complete without usable text or with a transform failure. `DictationSession.transcribed` emits `.hideHUD` for nil raw before its generation-aware `finishTail` (`Sources/ParlaCore/DictationSession.swift:464`). `handle(.commandHeard)` emits an error for empty instruction (`:412`), and `.legUnavailable` unconditionally emits an error (`:423`). `transformReady` emits errors for empty/oversized output before checking generation (`:658`, `:665`, `:682`). These routes are reachable from the async interpreter (`AppDelegate.transform`, `Sources/Parla/Dictation.swift:401`, `:424`). `perform` executes HUD effects without session identity (`:182`, `:192`); error toasts schedule hiding (`HUD.show`, `Sources/Parla/HUD.swift:322`). Thus B can keep recording while its listening indication disappears or becomes A's error.

Useful improvement: apply foreground-generation ownership consistently to completion HUD/hide effects while retaining intended history and raw-delivery semantics. Add focused stale-empty and stale-failure reducer cases. Existing stale cleanup and successful-transform tests already establish the desired silent-background precedent (`Tests/ParlaCoreTests/DictationSessionTests.swift:723`, `:866`).

**Strongest argument against:** effect ordering and generation-aware tails protect the actual state, menu bar and unload policy; successful pending cleanup and successful stale transforms already avoid the HUD. Errors can also be useful feedback. Those safeguards narrow this to presentation ownership; they do not suppress the identified effects. Current-session failure tests (`:807`, `:816`, `:889`) do not establish a deliberate stale-error exception.

**DOES-NOT-HOLD — a canceled capture's late streaming hop can simply resume typing or resurrect its ledger.** Cancellation consumes a generation (`DictationSession.handle`, `Sources/ParlaCore/DictationSession.swift:375`). `AppDelegate.stream` rechecks `capturing(gen)` after inference and again inside its main-actor hop before preview/typing (`Sources/Parla/Dictation.swift:516`, `:527`); `.streamTyped` checks generation (`DictationSession.swift:393`). `testLateStreamTypedAfterCancelCannotResurrectTheLedger` (`Tests/ParlaCoreTests/DictationSessionTests.swift:516`) directly covers the reducer half. Production additionally hard-disables live field typing (`Sources/Parla/main.swift:31`).

**Strongest argument against:** synchronous inference may take time to abort, and already-posted OS events cannot be recalled. This is source evidence for rejecting subsequent stream output, not a runtime latency guarantee or a promise that unrelated older finalized sessions cannot land.

**HOLDS — canceling pending recognition/formatting would be a product extension.** There is currently no user cancellation route after capture; both hotkey routing and the reducer enforce that deliberately. An explicit “discard pending delivery” action could help when formatting is slow. Define history retention and background computation separately: generation invalidation already prevents stale pending insertion, but does not stop the serialized cleanup await from delaying newer recognition (`AppDelegate.finish`, `Sources/Parla/Dictation.swift:359`).

**Strongest argument against:** existing behavior is coherent, documented and tested; users may prefer every spoken result preserved. A new fn press already invalidates older pending insertion. This is an optional workflow improvement, not a demonstrated violation of today's cancellation contract.

## Things checked that were fine

- Main-thread hotkey delivery preserves decision order; external capture endings do not unlatch queued presses (`HotkeyMonitor.emit/endSession`, `Sources/ParlaCore/Hotkey.swift:395`, `:405`; tests `HotkeyTests.swift:209`, `:223`). Capture-end generation is sampled before hopping to main (`Sources/Parla/main.swift:182`; session test `:633`).
- Stream-window disposal waits behind the exiting pass; stream exit unconditionally overwrites the window, including nil (`Sources/Parla/Dictation.swift:76`, `:551`).
- Pending cleanup rejects changed generation, target or new selection; terminal output/caret movement alone deliberately does not invalidate identity (`Dictation.swift:365`; `InsertionDestination.matches`, `Sources/ParlaCore/InsertionDestination.swift:19`; destination tests `:24`, `:32`, `:40`). Deferred stale delivery is explicitly tested (`DictationSessionTests.swift:143`).
- Secure-focus checks suppress delivery; recording resolution deletes secure audio even without a transcript (`Dictation.swift:246`, `:324`, `:346`; `RecordingStoreTests.swift:84`). Transform failures never fall back to typing the spoken instruction.
- Native paste is posted immediately; its delayed callback restores clipboard ownership, not a deferred transcript insertion (`Inserter.insert`, `Sources/ParlaCore/Inserter.swift:24`; `ClipboardDelivery.paste/restore`, `Sources/ParlaCore/ClipboardDelivery.swift:41`, `:67`). Old restore callbacks and intervening user copies are protected (`ClipboardDeliveryTests.swift:47`, `:56`).

# Feedback ownership check

**HOLDS — narrow conclusion:** after A stops and B starts recording, A's empty-transcript and early-failure completions can hide or replace B's recording HUD. B's reducer state and menu bar remain protected. This is inconsistent with the explicit newer-session HUD ownership used for cleaned completions and valid transforms; it is not true of every failure path.

Evidence (paths relative to `/Users/daksh/mySpace/code/wisper`):

- `DictationSession.handle` accepts a new dictation in every state and increments `gen` (`Sources/ParlaCore/DictationSession.swift:290`); `recorderStarted` emits B's listening HUD (`:314`). `transcribed` emits `.hideHUD` for `raw == nil` before calling the generation-aware tail (`:460`, `:464`). `commandHeard` emits “No command heard” without an ownership check (`:412`); `legUnavailable` likewise emits its error unconditionally (`:423`). `transformReady` emits errors for empty/oversized results before its generation check (`:658`, `:665`, `:682`).
- `finishTail` and `transformTail` suppress stale state/menu/unload changes, not preceding HUD effects (`Sources/ParlaCore/DictationSession.swift:440`, `:448`). Conversely, `cleanReady` suppresses stale HUD even for cleanup failure (`:582`, `:608`, `:613`), and valid stale transforms park silently (`:670`, `:682`). Under that documented ownership policy, A may retain history/log/trace effects, while B keeps recording feedback.
- No caller filter: `AppDelegate.finish` sends `.transcribed` regardless of generation (`Sources/Parla/Dictation.swift:316`, `:340`), including nil from silence or transcription failure (`:296`; `Sources/ParlaCore/Pipeline.swift:28`). `AppDelegate.transform` sends early errors/empty instructions and caught failures without generation checks (`Sources/Parla/Dictation.swift:380`, `:390`, `:401`, `:408`, `:424`). Its final ownership check only avoids stale AX probing; `.transformReady` is still sent (`:429`, `:441`).
- `AppDelegate.perform` directly forwards `.hud` and `.hideHUD` (`Sources/Parla/Dictation.swift:182`, `:192`); its insertion-failure substitution applies only to done/rawFallback. `HUD.hide` always settles (`Sources/Parla/HUD.swift:339`, `:224`); `HUD.show(.error)` hides recording indicators, replaces the label, and schedules settlement after 1.2 seconds (`:322`, `:353`). `HUD.dismiss` protects non-toast states only for dismissal, not show/hide (`:348`). A subsequent B HUD update can restore the pill and cancel the timer (`:230`), but is not guaranteed before A's effect.

**Timing/serialization:** `processTask` serializes stream/final/transform work (`Sources/Parla/Dictation.swift:84`, `:102`, `:109`), not recorder startup (`:52`). B can therefore capture while its stream awaits A. Main-actor completion delivery and the ordered reducer drain (`Sources/ParlaCore/DictationSession.swift:266`) serialize effects but do not reject stale events. No runtime reproduction performed.

**Strongest counterargument:** raw finalization is explicitly ungated so spoken text is delivered (`Sources/ParlaCore/DictationSession.swift:456`), and `testStaleTranscriptStillLandsButNeverTouchesTheNewerSession` tests this exception while checking state/menu/unload, not HUD (`Tests/ParlaCoreTests/DictationSessionTests.swift:710`). Failure visibility might be an intended independent notification policy. However, neither text preservation nor that test establishes a reason to hide B on an empty result, and no inspected comment/test explicitly endorses stale error feedback.

**Deliberate behavior separately:** ungated nonempty raw delivery is deliberate; stale cleaned/valid-transform silence is deliberate (`Sources/ParlaCore/DictationSession.swift:613`, `:670`). Current-session empty/error feedback is tested (`Tests/ParlaCoreTests/DictationSessionTests.swift:444`, `:807`, `:816`, `:889`). Those tests do not cover B recording. Stale silence is tested for deferred cleanup, cleaned swaps, and valid transforms (`:143`, `:723`, `:866`). No stale empty/error test found.

**Things checked that were fine:** stale tails preserve B's state/menu/model; stale cleanup (including fallback) emits no HUD; valid stale transforms preserve selection and can retain history silently; stream previews reject stale generations (`Sources/ParlaCore/DictationSession.swift:398`); capture-end ownership is checked at source/delivery (`Sources/Parla/main.swift:182`).
