# 09 — UX Patterns

Every dictation app in the corpus solves the same six UX problems: *how do I start it*, *how do I know it's listening*, *where did my text go*, *why did it fail*, *how do I get permission*, and *how do I get my text back*. This doc extracts the specific, cited mechanisms each app uses, ranks the ones worth copying, and ends with an ordered backlog for Parla.

Scope note: insertion mechanics live in `08-insertion.md`; this doc covers only the surfaces the user sees and touches.

---

## 1. Hotkey schemes and modes

### 1a. Defaults across the corpus

| App | Default trigger | Modes offered | Rebindable | Source |
|---|---|---|---|---|
| **Parla** | fn/Globe (63) hold | PTT, fn+Space latch, ⇧+fn command | **No** — hard-coded keycodes | `Sources/ParlaCore/Hotkey.swift:51,98,102`; Hub says "Shortcuts are fixed in this version." (`Hub/HubPages.swift:83`) |
| Handy | ⌥Space (mac) / ⌃Space | PTT (default true), toggle | Yes, 2 backends | Handy `src-tauri/src/settings.rs` |
| FluidVoice | Fn/Globe | toggle, hold, **automatic (400 ms tap/hold)** | Yes | FluidVoice `GlobalHotkeyManager.swift:73` |
| VoiceInk | ⌘⇧Space + modifier-only | toggle, PTT, hybrid, middle-click | Yes | VoiceInk `Shortcuts/` |
| yap | ⌘⇧D | **hold/latch from one 500 ms threshold** | Yes | yap `packages/desktop-utils/src/activation.ts` |
| macparakeet | Right-Option hold (PTT) | doubleTapAndHold / doubleTapOnly / holdOnly / singleTapToggle | Yes, incl. combos + F13–F24 | macparakeet `STT/FnKeyStateMachine.swift`, `HotkeyGestureController.swift` |
| Muesli | Fn/Globe | toggle, PTT | Yes | Muesli `Input/HotkeyMonitor.swift` |
| voicetypr | ⌥Space | PTT, toggle | Yes | voicetypr `crates/keytrigger` |
| hyprwhspr | **Right-Alt hold** | toggle, PTT | Yes | hyprwhspr `keyboard_backends/base.py:95,103` |
| parrot | fn/Globe hold | hold only | No | parrot `Sources/parrot/Input/HotkeyMonitor.swift` |

**Two defaults changed after user complaints.** hyprwhspr moved off `ctrl+ctrl`/toggle to Right-Alt PTT because "double-tap Ctrl collides with common desktop/app shortcuts out of the box" (`keyboard_backends/base.py`), pinning existing installs to the old default via an explicit migration so an upgrade never silently changes behavior (`config_manager.py:193-225`). voicetypr's issue #295 is a KDE user whose Ctrl+Enter binding was hijacked with no way to disable — *"undesired takeover of a shortcut used extensively by many other programs"*.

**Rebindability is the #1 hotkey complaint everywhere.** voicetypr: 35 hotkey issues, #302 "can't set a hotkey which is one key, like Command or right shift". vocalinux: #395/#324 with 2 reactions each, "let me pick any key". macparakeet #153 (5 reactions, open) wants the Fn key on macOS specifically because it's what MacWhisper/superwhisper users expect. **Parla is the only app in the corpus with zero rebinding and it admits it in-product.**

### 1b. The unified hold/tap threshold (yap, FluidVoice, macparakeet)

yap's `ActivationController` gets PTT *and* latch from a single binding and a single constant:

```ts
// packages/desktop-utils/src/activation.ts
TAP_THRESHOLD_MS = 500
// on release: elapsed < TAP_THRESHOLD_MS ? latch (next tap stops) : stop
```

FluidVoice uses the same idea at 400 ms (`GlobalHotkeyManager.swift:73` `automaticTapThresholdSeconds: TimeInterval = 0.4`), and macparakeet emits `.scheduleStartupDebounce(100ms)` *and* `.scheduleHoldWindow(tapThresholdMs)` on trigger-down, starting capture speculatively at 100 ms and discarding it if the release comes early (`STT/FnKeyStateMachine.swift`, `defaultStartupDebounceMs = 100`, `defaultTapThresholdMs = 400`).

Parla already has the speculative-start half — recording begins on fn-down and a `< 0.2s` session is discarded (`Hotkey.swift:33`, `shortTapThreshold`). It just spends a second key (fn+Space) on what yap gets from the threshold.

### 1c. Cancel-key etiquette

Handy registers the cancel shortcut **only while recording** (`register_cancel_shortcut` on start / `unregister_cancel_shortcut` on stop) so Escape isn't stolen globally. TypeWhisper #302 is the cautionary tale: a permanently-armed CGEventTap consumed Escape system-wide and users could not exit insert mode in Vim; the fix (v1.9.0) was to consume the cancel binding only while a recording is active.

Parla already gets this right — `keyDown` returns `swallow: true` for Esc only when `session != .idle`, and passes it through otherwise with `.dismiss` (`Hotkey.swift:105`).

**Undo windows.** macparakeet gives Esc a 5-second `cancelCountdown` state with a visible countdown and an `undoCancel()` that re-transcribes the "cancelled" audio (`DictationFlow/DictationFlowStateMachine.swift`). VoiceInk uses double-Esc with a 2 s arming window and an animated draining bar. Parla's Esc is immediate and irreversible.

### 1d. VAD-based auto-stop is contested

Only hyprwhspr, Handy, TypeWhisper, and openwhispr ship silence auto-stop. hyprwhspr's numbers: `VOICE_RMS_THRESHOLD = 0.005`, `MIN_VOICE_DURATION = 300ms` sustained, warn at 10 s / 60 s, hard timeout at 300 s (`silence_detector.py`) — and it emits events only, never issues a stop from the audio callback, after issue #62/#136 where Bluetooth headsets emitting 1 s of digital silence during A2DP→HSP renegotiation cancelled every recording.

vocalinux #201 frames auto-stop as an **accessibility requirement**: *"manual-stop is a real barrier for users with limited hand mobility"*. But voicetypr #860's own thread pushes back: *"I prefer push-to-talk like Wispr Flow… sometimes I'm thinking and it decides I'm done."* Ship it as an option with a configurable threshold, defaulted off.

## 2. HUD / overlay design

### 2a. Window class is the load-bearing decision on macOS

Epicenter's `src-tauri/src/overlay.rs` docstring is the clearest statement in the corpus:

> "a plain always-on-top `WebviewWindow` still activates the app when clicked: `focusable: false` only blocks keyboard focus, not application activation."

Their fix is `tauri-nspanel` with `can_become_key_window: false`, `is_floating_panel: true`, `StyleMask::empty().nonactivating_panel()`, `accept_first_mouse(true)`, `PanelLevel::Status`, `can_join_all_spaces() | full_screen_auxiliary()`. Pindrop reached the same conclusion independently (`docs/recording-overlay.md`: *"On macOS it is a non-activating `NSPanel` created in Rust (via tauri-nspanel)… `focusable: false` alone does not prevent app activation on click"*, citing tauri#9556/#11488). ghost-pepper and Muesli both use raw `NSPanel([.borderless, .nonactivatingPanel])`.

**Parla already does this correctly**: `NSPanel(styleMask: [.borderless, .nonactivatingPanel])`, `.level = .statusBar`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`, clear background so clicks pass through everywhere except the opaque pill (`Sources/Parla/HUD.swift:89-101`).

### 2b. Overlay geometry across the corpus

| App | Size | Position | Source |
|---|---|---|---|
| **Parla** | 260×44 pill in a 284×68 panel, radius 22 | 4-edge dock + offset, persisted | `HUD.swift:39`, `dockOrigin` |
| Handy | 256×46 pill / 400×120 streaming card | top/bottom | Handy `overlay.rs` |
| voicetypr | 240×48 | user-selectable display | voicetypr `osd/` |
| vibe | 280×64, 48 px bottom margin | **cursor's monitor** | vibe `dictation_indicator.rs:97-125` |

| Muesli | 224×40 pill, radius h/2 | bottom-center, 72 pt up | Muesli `Services/OverlayScreenResolver` |

### 2c. Pre-create the overlay hidden at launch

vibe's `setup.rs:124` calls `dictation_indicator::initialize(app.handle())`, which builds the window at boot and hides it, with an `on_page_load` guard that re-hides if no session is active. openwhispr does the same at process level: the GTK overlay is spawned once at service start and toggled with SIGUSR1/SIGUSR2 — *"eliminates subprocess spawn latency on each recording"* (`lib/mic_osd/runner.py`). ghost-pepper's `HUDController.prepare()` builds the `NSPanel` + `NSHostingView` at launch and only `orderOut`s on hide: *"creating it on first use rendered an unlaid-out window for a frame — a flicker before 'Listening' appeared."*

Parla constructs its HUD in `AppDelegate` at launch already; the pill and panel are long-lived (`HUD.init`).

### 2d. Session-generation-guarded dismissal — Parla already satisfies this

vibe `dictation_indicator.rs:213-222`: `hide_dictation_indicator(session_id)` **mutates nothing unless `current.session_id == session_id`**, and the frontend bumps a monotonic `indicatorSessionRef` per session and captures it in the auto-hide `setTimeout`.

> With 1.5 s success / 3.5 s error auto-hide and a user who dictates in rapid bursts, an un-guarded timer from session N hides session N+1's HUD — a bug that is maddening to reproduce and trivial to prevent.

**Verified against Parla: not a bug here.** vibe needs a generation id because its hide crosses a process boundary. Parla's hide is a `DispatchWorkItem` stored in `hideItem` and both `show(_:)` (`HUD.swift:213-215`) and `settle()` (`HUD.swift:207-208`) `cancel()` + nil it before doing anything else, all on the main queue — so a dictation started inside the 1.2 s window cancels the previous timer rather than being hidden by it. A cancelled `asyncAfter` item does not execute. No change needed; the corpus pattern is a rediscovery of what Parla does structurally.

### 2e. Screen-capture invisibility

TypeWhisper makes it a user setting: `panel.sharingType = isVisibleInScreenCaptures ? .readOnly : .none`, so the HUD can be hidden from Zoom/QuickTime. TypeWhisper's meeting notifications go the other way — deliberately content-protected so they never leak into a screen share. Nobody else in the corpus handles this. Parla does not set `sharingType`.

### 2f. Streaming preview belongs in *your* overlay, not the target app

vibe `Sources/MacParakeetCore/Services/OverlayStreamingSink.swift` states the rule outright:

> "renders the live transcript in Parla's own floating-indicator overlay instead of typing into the target app. The target app receives the final text exactly once, via a single atomic paste when the session finishes — **there is no live keystroke synthesis, no diffing, and nothing to undo on cancel**."

Epicenter arrived at the same design (`docs/adr/0016`, `StreamingRefinementCoordinator.swift`): partials are display-only; insertion is single-write after cleanup. Epicenter's ADR-0099 spells out the race: delivering raw then polished "would land two copies (a clipboard the user might paste mid-polish, or two cursor pastes)."

Parla already runs a shadow stream with `liveTyping` hard-disabled (`main.swift:179`) — the confirmed prefix exists but nothing renders it. **The overlay is the missing consumer.** Its label frame is already sized for the case (`158,12,92×20` while listening vs `16,12,228×20` otherwise, `HUD.swift`).

## 3. Waveform / level feedback

Everyone draws bars from RMS. The differences are in the perceptual curve and the animation.

**parrot** (`Sources/parrot/UI/RecordingOverlay.swift:92-113`) — 6 bars, and the three tricks that matter:

```swift
shaped = min(1.0, sqrt(max(0, level)) * 3.4)          // perceptual curve
envelope = [0.55, 0.85, 1.0, 1.0, 0.85, 0.55]          // fixed centre-weighted shape
jitter   = Float.random(in: 0.78...1.0)                // per-bar, "so the bars don't all move in lockstep"
// animation: .easeOut(duration: 0.09)
```

**macparakeet** `AudioLevel.normalized` maps dB with floor −45 / ceiling −10 then `pow(linear, 0.7)` — *"Speech typically sits between −45 dB (room tone) and −10 dB (talking)… otherwise everything bunches into the middle and the meter barely moves."* Its `HUDController.setLevel` uses **asymmetric smoothing**: attack 0.75, release 0.22 — *"Very fast attack keeps transients visible; gentler release lets the trace fall away instead of collapsing between syllables."* Bars fade with age (`opacity = 0.28 + 0.57 * age`) *"so speech leaves a visible trace instead of the whole meter rising and falling as one."*

**Parla** (`HUD.swift:435-462`): 30-sample ring, 3 pt bars + 1 pt gap, `norm = min(1, level * 8)`, min height 2 pt, redrawn only on real pushes (no timer). Linear gain, no perceptual curve, no smoothing, no envelope, no jitter, no age fade. It is the simplest waveform in the corpus and it is the only one with a linear amplitude mapping.

**Emission rate matters more than the drawing.** Handy's `EMIT_THROTTLE_MS = 33` (~30 FPS) plus a cached `OVERLAY_ENABLED: AtomicBool` exists because *"reading the Tauri store on every audio callback (~24 Hz during recording)"* was measurable. vocalinux #491 is the extreme case: audio-level events emitted at cpal's native **~185 Hz** straight to the WebView caused **5-second system-wide freezes** on a 32 GB/5070/14600K machine; the fix throttled to 30 Hz. Parla emits from the audio thread and hops to main per chunk (`main.swift:98-100`) with no throttle — safe today only because it draws into an `NSView` rather than a webview.

## 4. Sound design

| App | Start | Stop | Cancel | Volume | Source |
|---|---|---|---|---|---|
| **Parla** | **Tink** | Glass | **Funk** | 0.25 | `Sources/Parla/main.swift:8-18` |
| yap | Purr | Glass | — | default | yap `HUD` |
| macparakeet | Tink | Pop | — | — | macparakeet `SoundController` |
| Handy | selectable themes + volume | ✓ | ✓ | user | Handy settings |
| hyprwhspr | 3 bundled OGGs, "smooth gliding tones, headphone-friendly" | ✓ | ✓ | toggleable | hyprwhspr `audio/feedback.rs` |

yap's `HUD.swift` carries the note Parla should read:

> "Deliberately avoiding Tink/Basso/Sosumi/Funk, which macOS uses for alerts and errors — they make a normal start-of-dictation feel like something went wrong."

Parla uses **Tink for start and Funk for cancel** — exactly two of the four yap names. ghost-pepper's `2c58915` commit is the same finding independently: they shipped Tink, and *"Tink is what macOS uses for alerts, so starting dictation sounded like an error"*, changed to Purr/Glass.

**Ordering vs capture is the harder problem.** Three apps hit it:

- **hyprwhspr** `verify_and_play_sound()` (`lib/main.py:1105`) polls `frames_since_start > 0` every 50 ms for up to **1.5 s** before playing the start sound, then `verify_stream_stable()` sleeps 200 ms and requires the counter to have *increased again*, else tears down with "Microphone stream unstable." The beep becomes a truthful signal.
- **FluidVoice** gates `onCaptureStarted?()` — start sound, AX focus snapshot, LLM prewarm — behind `AudioCaptureReadinessGate.wait(timeout: 2_000_000_000)`, with 3 attempts and a 300 ms settle. `ASRService.swift:1587`.
- **Handy** starts capture first, then sleeps 100 ms **on a separate thread** before the beep + mute, so the cue never blocks capture.

And the cue leaks into the recording: hyprwhspr's #150 → #426 → #436, three PRs, landing on `stop_sound_guard_ms = 200` — trim ~3 chunks off the tail after the stop chime so whisper doesn't transcribe it. Parla plays Glass after `recorder.stop()` returns, so this is not currently a hazard.

**Parla has no mute toggle.** `Sound.play` no-ops if `NSSound(named:)` returns nil, but there is no setting. Handy, hyprwhspr, ghost-pepper, and Muesli all ship one; hyprwhspr got four separate issues asking for independent control of sounds vs. muting (#104, #105, #58, #122).

## 5. Permissions and onboarding

### 5a. macOS AX grant loss — the single most expensive support burden in the corpus

Four independent projects hit the identical bug:

| Project | Symptom | Root cause | Fix |
|---|---|---|---|
| openwhispr #6 (19 comments), #14 (5 reactions — top-reacted issue in the repo) | Re-prompts for Accessibility on *every* launch; users clicked "Allow" **10× per push-to-talk press** | `xcodebuild` without an explicit signing identity produces `Signature=adhoc, linker-signed` with `Info.plist=not bound` / `Sealed Resources=none`; TCC keys grants off the bound bundle identifier | PR #19: real signing; PR #25: sign nested Sparkle executables; `codesign --verify --deep --strict` as a **hard release gate** |
| VoiceInk #108 (16 comments) | App appears in Accessibility list and enabled, shortcuts silently dead | stale TCC row after update | must revoke *and* re-grant both Accessibility **and** Input Monitoring around every update |
| Muesli #6/#25 | System Settings shows ✅ while `AXIsProcessTrusted()` returns false | ad-hoc signing → cdhash changes every build | ships a **`tccutil reset Accessibility <bundleid>` button** in-app |
| ghost-pepper #108 | same | same | same |

**Parla already has the packaging half of this fix** — `scripts/make-app.sh` signs with a stable designated requirement `identifier "com.parla.app"` (documented in `ISSUES.md` §4). It does **not** have the user-facing recovery half.

### 5b. The dead-tap: `AXIsProcessTrusted()` returns true and the tap never fires

Handy's `keyboard/mac_tap.rs` runs a `ListenOnly` CGEventTap *purely as a liveness probe*, because after an app update macOS can return `AXIsProcessTrusted() == true` while silently dropping every synthetic event, and there is no API to detect it. Their supervisor folds tap liveness with trust into a 5-state capability (`Unknown/Inactive/Untrusted/Active/Broken`) with `[1,2,4,8,16]s` backoff, a 60 s reset window, and `Broken` gating insertion.

macparakeet's version is simpler and directly portable: if Accessibility isn't granted when the tap starts, the tap is created **dead and never revives**, so it polls `AXIsProcessTrusted()` every 2 s and, once granted, deletes the lockfile, re-spawns itself with the same argv, and `exit(0)` (`Sources/MacParakeetCore/.../hotkey_macos.rs:84-113`).

Parla's mitigation is `HotkeyMonitor.start()` retrying tap creation every 3 s forever (`Hotkey.swift:126-129`) plus `tapDisabledByTimeout/ByUserInput` re-enable (`:138-140`). That covers *creation failure* and *runtime disable* but **not** the trusted-yet-dead case, and the 3 s retry loop `NSLog`s forever without ever escalating to the user.

### 5c. Onboarding

Nobody in the corpus ships a dictation app without one except Parla and parrot.

- **ghost-pepper** `PermissionChecker.swift` has the best single idea: a `RunningAppDragTile` with a custom `NSDraggingSource` that lets you **drag the running app's icon straight into the System Settings permission list**, with its full path shown selectable underneath — because "click +, navigate to Applications" is where users get lost, *and because the running bundle may not be the one in /Applications*.
- **macparakeet** `UI/Onboarding/OnboardingFlowView.swift` (1,116 lines): `welcome → permissions → model → hotkey → tryout → AI enhancement → finish`, with a **live dictation tryout** routed to a sandbox sink (`DictationOutputRoute.onboardingSandbox`) that suppresses clipboard/history/external typing, and a 180 s warm-up stall watchdog that resets on every progress event.
- **Handy** forces the window visible if permissions are missing, overriding `--start-hidden`.
- **Muesli** `PermissionsManager` calls the AX prompt from an explicit user click only, after the run loop is up, with the rationale in-source: calling `AXIsProcessTrustedWithOptions([prompt:true])` from Tauri `setup()` can make macOS mark the prompt "already shown" without showing it, and thereafter it never appears (issues #662, #652, #725).

**Parla calls `AXIsProcessTrustedWithOptions([prompt: true])` on every launch while untrusted** (`main.swift:788-791`) — precisely the pattern Muesli root-caused as harmful.

### 5d. Permission observation

Handy/FluidVoice/Muesli all *observe* rather than poll: `DistributedNotificationCenter` on `com.apple.accessibility.api` (Muesli, `PermissionsManager`), plus `NSWorkspace.didActivateApplicationNotification`, plus an adaptive poll (1 s while waiting, 5 s once granted, `tolerance = interval/4`, `.common` run-loop mode "so it keeps firing while a menu is being tracked"). Muesli's note: *"none alone is dependable."*

Parla samples `micGranted`/`axGranted` only on menu open and after a dictation, and polls at a flat 2 s while the Hub is open (`HubPages.swift:8`), forcing a full SwiftUI re-render — which also re-runs `micOptions`, a full Core Audio device enumeration, every 2 seconds (`HubPages.swift:114-121`).

## 6. Settings surface organization

The corpus splits cleanly into two failure modes.

**Too big:** FluidVoice `SettingsStore.swift` is **5,336 lines** with ~400 computed properties, each calling `objectWillChange.send()` on write; openwhispr #274 measured the consequence — **80–170 ms to main-thread idle per keystroke** in a settings text field, 3 SwiftUI view bodies rebuilt per keystroke, a ~12 keystrokes/sec ceiling. VoiceInk `SettingsView.swift` 4,444 lines. TypeWhisper 3,944 lines — big enough that they built `SettingsSearchIndex.swift` and a searchable sidebar (v0.15.0).

**Too small:** parrot has flags only, no persistence. Parla is closest to this end: 6 Hub pages, no search needed, and the settings that exist are honest.

Two organizational ideas worth stealing:

1. **Handy's debug mode** — `Cmd/Ctrl+Shift+D` unlocks a live log viewer, log level, paste delay, reliable-paste toggle, extra recording buffer, word-correction threshold, keyboard-implementation selector, keyboard diagnostic, debug paths, and what's-new preview. Keeps the tuning knobs out of the main surface without hard-coding them.
2. **voxtype's config-mismatch banner** — `variant_check::detect_mismatch` (PR #455) surfaces "your configured engine doesn't match your installed binary" as a persistent banner in the settings UI *and* a startup notification from the daemon, because *"logs go to journald and most users never see them"*. Parla's Hub already does the honest version of this for cleanup config (`configIssue` calls the real `makeCleanupClient` so the banner can't drift from runtime, `HubPages.swift:147-162`) — worth extending to model/permission state.

Anti-pattern to avoid: Handy's own weakness list flags **~40 single-purpose `change_*_setting` Tauri commands, one per boolean** — "A single `update_settings(patch)` would have done." Parla's `HubModel` debounced whole-file save (`HubModel.swift:111-138`) is already the right shape.

## 7. History and recovery UX

### 7a. Never lose the audio

The strongest pattern in the corpus, arrived at independently three times:

- **Muesli** `Services/DictationRecoveryAudioStore.swift` — streams the dictation to a 16 kHz mono PCM WAV *during* recording, with a user-visible retention policy (`immediately / 1 / 7 (default) / 30 / 60 / 90 / 180 / never` days) and a Recovery UI. Driven by issue #533: "Recorded audio is lost when transcription fails under load" — two independent loss paths, one where the transcription throws and the local `[Float]` samples go out of scope, one where the config-change circuit breaker calls `clearRecordingBuffer()` before the view model is notified.
- **Handy** — a failed transcription **still writes an empty-text history row** so the user can retry from the saved audio; `verify_wav_file(path, sample_count)` after save, and a failed verify skips the row rather than promising recoverable audio that isn't.
- **voicetypr #85** — a 10-minute recording lost forever to an OpenAI timeout because audio lived only in a `BytesIO`. The reporter's dig is the lesson: *"The function `save_audio_to_wav()` exists in `audio_capture.py:920` but is never called."*

**Parla never persists audio at all.** A whisper failure, an insertion refusal, or a crash loses the utterance. Its eval corpus has to be recorded separately with `sox` (`eval/README.md`).

### 7b. Interruption ≠ end of recording

Epicenter's `recorder/recorder.rs` has the cleanest model: an unplugged mic ends *capture* but not the *recording*. The slot stays occupied, the staged WAV stays on disk, `current()` keeps answering with a typed `EndedReason` (`deviceDisconnected | permissionRevoked | streamFailed | storageFailed`), and only the owner's `stop`/`cancel` resolves it — so the ordinary stop path still finalizes and transcribes it. No pending-interruption inbox, no acknowledgement protocol.

### 7c. History contents

| App | Cap | Stores | Extras | Source |
|---|---|---|---|---|
| **Parla** | 50 | raw, cleaned, appName, date | paste-last, Recent×8 submenu | `Sources/ParlaCore/History.swift:22` |
| Handy | unbounded (SQLite) | raw, post-processed, prompt used, WAV | retry from audio, failed rows kept | Handy `history.db` |
| VoiceInk | SQLite | + `aiRequestSystemMessage`/`aiRequestUserMessage` per row | "when cleanup goes weird, you can see the exact prompt" | VoiceInk `SessionMetric` |
| Pindrop | SwiftData | + audio, + `PipelineMetrics` JSON | re-transcribe from history | Pindrop `Models/TranscriptionRecordSchema.swift` |
| voicetypr | JSON | raw + processed | — | voicetypr |
| macparakeet | Library (SQLite) | + audio + speaker turns | full-text search, export | macparakeet `Lab/TranscriptionLabStore.swift` |

**Handy's Transcription Lab / macparakeet's `TranscriptionLabStore` are the same idea**: archive every real dictation (WAV + OCR context + raw + cleaned + model IDs + per-stage timings, ring-buffered at 50, orphan-audio pruned) and let the user re-run transcription *or* cleanup on archived audio with a different model or prompt. That is a golden-file eval corpus built out of production traffic — with an `expectedOutput` field it becomes a regression bench for free.

`ISSUES.md` next-step #4 ("Route no-focus dictations into the Scratchpad") is Parla's version of the same gap: history is currently the only landing for a no-focus dictation.

## 8. Error states and honest failure copy

### 8a. Delivery is an axis, not a boolean

Epicenter `docs/adr/0039`: `DeliveryReach = 'output' | 'clipboard'` — **both are successes** because the transcript is always saved. Failures are separately tiered `'silent-loss' | 'transcription'`. And the UI carries the distinction: a clean `delivered` with `reach: 'output'` auto-retires after `DELIVERED_FLASH_MS = 900`, but a reduced `reach: 'clipboard'` **persists until the next dictation because it carries information the pasted text does not** (`state/dictation-lifecycle.svelte.ts`).

Parla's state enum is already this shape — `.done` / `.savedToHistory` / `.cleanedInHistory` / `.rawFallback(reason)` / `.error(msg)` map 1:1 to real outcomes (`HUD.swift:8-19`). What it lacks is the differentiated dwell.

### 8b. Auto-hide durations

| App | Success | Non-fatal | Error | Source |
|---|---|---|---|---|
| **Parla** | 1.2 s | 1.2 s | **1.2 s** | `HUD.swift:302` |
| Muesli | 0.8 s | 2.5 s (noSpeech) | **5 s** | Muesli `IndicatorWindowManager` |
| ghost-pepper | 1.5 s | 2.5 s (no mic) | **5 s**, interactive | ghost-pepper `UI/RecordingOverlay.swift` |
| vibe | 1.5 s | — | **3.5 s** | vibe `dictation_indicator.rs` |
| openwhispr | 2.5 s flash, no queue, new message resets timer | — | — | openwhispr `docs/pill-flash-message.md` |

Every app that shipped errors and successes on the same timer eventually split them. Parla hasn't.

### 8c. Classified errors beat generic strings

Handy's `recording-error` event carries a classified `error_type`: `microphone_permission_denied` (matched on "access is denied" / "permission denied" / `0x80070005`), `no_input_device`, `unknown` — and reverts the overlay/tray rather than leaving them stuck. FluidVoice's `recordingErrors.ts` gives distinct titles for `NotAllowedError`, `NotFoundError`, `NotReadableError` ("Microphone In Use"), and a custom `MicUnusableError` ("Your microphones stayed muted and produced no audio").

Compare hyprwhspr #183, where "device changes not picked up" masqueraded as an audio bug for 20+ comments before the root cause turned out to be the *keyboard* listener losing its device across suspend. Classification is diagnostic infrastructure, not polish.

### 8d. Recoverable failure states

FluidVoice keeps the overlay up holding `pendingAIReprocessText` after an LLM failure, so **one click retries just the AI pass** on the already-captured transcript. Parla's equivalent (`.rawFallback(reason)`) is informational only — the cleaned text is unrecoverable without going to the Hub.

### 8e. Errors the corpus says you must never show as success

- ghost-pepper `#218`: `hyprctl dispatch` printed "Invalid dispatcher" on **stdout** and **exited 0**; the app cached the broken path and still logged `[INJECT] Text injected (N chars)`. **Silent total paste failure with a success log.**
- hyprwhspr #552: eitype returned exit 0 while truncating a 220-char transcription at 164 chars, so the clipboard fallback never fired.
- The rule both derive: *verify the effect, not the call*. Parla's `Inserter.canEraseTyped` does this for the swap; nothing verifies the initial insertion landed.

| Element | Who does it | Parla |
|---|---|---|
| Icon swaps while recording | Handy (`studio_microphone.png` ↔ `red_large_square.png`), VoiceInk, ghost-pepper (red-dim / orange ellipsis / yellow triangle) | ✓ (`showRecording()`, ⚠️ on unhealthy — `main.swift:813-821`) |

| Copy/Paste last transcript | VoiceInk, Handy, Parla | ✓ (⌃⌘V + Recent×8) |
| Prompt/preset switching from the menu | VoiceInk (v1.22.0 — "no settings round-trip") | ✗ |
| Update-available item | Handy, Parla | ✓ |
| Close-to-tray / minimize-to-tray | **voicetypr #848: 18 reactions, the highest-reacted issue in that repo**, plus #714 (11), #199 (8), #607 (5) — a *regression*, the option had existed and was removed | n/a (Parla is `.accessory`-only) |

**Menu-bar-only mode is a bug farm elsewhere and Parla dodges it.** Muesli logged #383 (window closes on any click when Dock icon hidden), #368 (app quits when the icon is hidden by macOS 26.1), #576, #412 — all from `NSApp.setActivationPolicy` races. Parla sets `.accessory` once at launch and never flips (`main.swift:1167`), using `NSApp.activate(ignoringOtherApps:)` for the Hub and Scratchpad instead. That is the safe shape.

**Menu rebuild cost.** Parla rebuilds the whole menu on `menuNeedsUpdate` — "cheaper than tracking diffs" (`main.swift:975-1041`) — but that path does `store.load()` (synchronous JSON decode) at least twice and a full Core Audio enumeration per open. VoiceInk instruments its own tray build (`⏱️ [TRAY BUILD TIMING]`) *because loading remote settings could block it*.

## 10. Multi-monitor

The corpus is a graveyard here.

- **Handy**: multi-monitor overlay was a recurring three-platform bug — #811 (Windows secondary monitors, 21 comments), #764, #1375 (Wayland) — across PRs #969 and #1733; `overlay.rs:249` notes the fix depends on tauri 2.11's `work_area.position.y` fix (tauri-apps/tauri#14655) — *"the same bug that led PR #969 to abandon work_area for full monitor bounds."*
- **voicetypr**: `NSScreen.main` follows keyboard focus, so the overlay hopped displays (#192). Fix: a "Show on" picker (Active window / Primary / specific screen) persisting the `displayID`, resolving back to primary when unplugged, live-updating on `NSApplication.didChangeScreenParametersNotification`.
- **vibe** `dictation_indicator.rs:97-125`: `cursor_position()` → `monitor_from_point()` → `primary_monitor()` → main-window position, with explicit scale-factor math (`x = mon.x + (mon.width - WIDTH*scale)/2`). *"dictation HUDs must appear where the user is looking, which is where the cursor is — not on the primary display."*
- **macparakeet** `Services/OverlayScreenResolver.swift` — the same order Parla uses.
- **Muesli** #1110: on X11 each display's `workArea` is derived from a **single global `_NET_WORKAREA`** and comes out wrong in *both* directions on mixed-DPI, with measured numbers (4K workArea cut by 236 DIP / ~402 px by the 1080p's panel strut).
- **ghost-pepper**: `NSScreen.main` only — a known gap.
- **openwhispr** PR #469: HiDPI bug where `pill_pos_on_monitor` scaled the workarea to physical px but used logical window size, shifting the pill down by `win_h * (scale - 1)` — on 5120×2880 @200% the pill landed 346 px below the screen. *"Invisible on scaled displays, perfect on scale-1, so it survives all normal testing."*

**Parla's `activeScreen()` is already best-in-class**: AX-focused element's screen → screen under mouse → `NSScreen.main` (`HUD.swift:385-395`). It anchors top/bottom off `visibleFrame` (respects Dock + menu bar) and left/right off `frame` (true edge), and clamps the pill center to stay fully within the span (`dockOrigin`). Nothing in the corpus does it better. No change needed.

Missing: no `NSApplication.didChangeScreenParametersNotification` observer, so unplugging the docked display leaves the pill on a screen that no longer exists until the next `show()`.

## 11. Updates

| App | Mechanism | Notes |
|---|---|---|
| **Parla** | GitHub Releases API poll, once at launch, 24 h throttle, opens browser | `Sources/ParlaCore/UpdateCheck.swift`; no download, no manual check |
| Handy | tauri-plugin-updater + minisign pubkey + what's-new modal gated on `whats_new_last_seen_version` | Handy `tauri.conf.json` |
| VoiceInk | Sparkle with the **scheduler deliberately disabled** — "VoiceInk owns automatic discovery through Sparkle's non-presenting probe. Keeping Sparkle's scheduler disabled prevents it from showing an update dialog" | VoiceInk `SimpleUpdater.swift` |
| FluidVoice | mxcl/AppUpdater + GitHub API, beta channel | *"releases are signed with Developer ID. Skip strict check to enable testing."* — a security smell left in the shipping update path (`SimpleUpdater.swift:423`) |
| voicetypr | Sparkle 2 | #745: **the update prompt interrupted an active dictation and discarded the transcript**; #780/#684/#616 → PR #782: menu-bar check and timer check both found the update and started parallel installs, launching two app versions — fixed with a trivial `UpdateOperationGate` bool |
| VoiceInk | — | #760: `SUAutomaticallyUpdate = 1` + an app users never quit → Sparkle's `Autoupdate`/`Updater.app` stayed alive **10 days** reparented to launchd, growing `launchservicesd` to **2.38 GB at ~22 MB/hour** with 7,282 LaunchServices entries |

Three rules the corpus establishes:
1. **Never interrupt an active dictation with an update prompt** (voicetypr #745).
2. **Never stage quit-time updates in an app the user never quits** (VoiceInk #760).
3. **Gate concurrent update operations** — a single `begin()/finish()` bool (voicetypr PR #782).

Parla's browser-only "update available" menu item is immune to all three, which is a legitimate design position for a 0.1.0 app. Its real gap is that `CFBundleShortVersionString` is hard-coded to `0.1.0` in `scripts/make-app.sh` and never bumped, so once any tag exceeds it the item shows forever.

## What Parla should do

Ordered by value-per-effort. Every item names the file it touches.

1. **Split the auto-hide by state.** `HUD.swift:302` — `.done`/`.savedToHistory` at 1.2 s, `.cancelled` at 1.2 s, `.error`/`.rawFallback` at 5 s, `.cleanedInHistory` at 3 s (it names a place the user has to go). Ref: Muesli 0.8/2.5/5, ghost-pepper 1.5/2.5/5. **Effort: S.**

2. **Change the start and cancel sounds.** `Sources/Parla/main.swift:8-18` — Tink → Purr, Funk → Pop or Bottle. Add `Settings.soundsEnabled` (default true) and a Hub General toggle. Ref: yap `HUD.swift`, ghost-pepper `2c58915`. **Effort: S.**

3. **Set `panel.sharingType = .none`** in `HUD.init` (`HUD.swift:89-101`), behind a Hub toggle defaulting to hidden-from-capture. Ref: TypeWhisper. **Effort: S.**

4. **Stop prompting for AX on every launch.** `main.swift:788-791` — call `AXIsProcessTrusted()` (no prompt) at launch and only call `AXIsProcessTrustedWithOptions([prompt:true])` from a Hub button / the menu's permission row. Ref: Muesli issues #662/#652/#725. **Effort: S.**

5. **Route the shadow-stream confirmed prefix into the HUD label.** `main.swift:735-752` currently guards on `liveTyping`; add an unconditional `hud.preview(confirmed + tail)` alongside it, and widen the listening-state label frame. Zero insertion risk — the pill is already the right size. Ref: vibe `OverlayStreamingSink.swift`, Epicenter ADR-0016. **Effort: M.**

6. **Gate the start cue on the first non-empty audio chunk.** `AudioRecorder.swift` already computes RMS per chunk (`onLevel`); add a one-shot `onFirstAudio` callback and move `Sound.start()` in `main.swift:106-190` behind it, with a 1.5 s timeout that surfaces `.error("Mic produced no audio")`. This also gives Parla a real dead-mic detector. Ref: hyprwhspr `verify_and_play_sound()`, FluidVoice `AudioCaptureReadinessGate`. **Effort: M.**

7. **Persist the recording WAV before transcription and keep failures.** New `Sources/ParlaCore/RecoveryStore.swift`; write from `AudioRecorder.stop()`'s returned samples in `finish()` (`main.swift:321`) before the whisper call, delete on success, keep on any failure path. Add a retention setting (default 7 days) and a Hub "Recovery" row. This doubles as the eval-corpus collector `eval/README.md` asks for. Ref: Muesli `DictationRecoveryAudioStore.swift`, Handy's empty-text history row. **Effort: M.**

8. **Rewrite the waveform math.** `HUD.swift:435-462` — `shaped = min(1, sqrt(level) * 3.4)`, a fixed centre-weighted envelope over the visible bars, per-bar `random(0.78...1.0)`, attack 0.75 / release 0.22 smoothing on the incoming level, and age-based opacity `0.28 + 0.57 * age`. Ref: parrot `RecordingOverlay.swift:92-113`, macparakeet `AudioLevel.normalized`. **Effort: M.**

9. **Add an Esc undo window.** `main.swift:234-237` (`.cancel`) → arm a 5 s `HUD.State.cancelPending` with a visible countdown; a second Esc confirms, expiry discards, and (with item 7) `undoCancel()` re-runs the pipeline on the saved WAV. Ref: macparakeet `DictationFlowStateMachine.swift`, VoiceInk double-Esc. **Effort: M.**

10. **Make hotkeys rebindable.** `Sources/ParlaCore/Hotkey.swift:51,98,102` — keycodes are hard-coded and the Hub advertises "Shortcuts are fixed in this version." (`Hub/HubPages.swift:83`). Add `Settings.hotkeys` and a recorder control. This is the single most-requested feature across voicetypr (35 issues), vocalinux, macparakeet (#153, 5 reactions) and openwhispr. Note the trap: use physical keycode + exact modifier match; Parla's `⌃⌘V` check (`keyCode == 9, cmd, ctrl`) currently also fires for `⌃⌘⇧V`. **Effort: M.**

11. **Add per-dictation `PipelineMetrics` to `HistoryEntry`.** `Sources/ParlaCore/History.swift` — one optional JSON column (`captureMs, asrMs, cleanupMs, insertMs, totalMs, model, cleanupModel`), one greppable log line per dictation, and a Hub History column. This is what makes every future latency claim falsifiable, and it costs ~80 lines. Ref: VoiceInk `SessionMetric`, Pindrop `Models/PipelineMetrics.swift`. **Effort: M.**

12. **Ship an in-app permission recovery path.** Hub General → a "Reset permissions" button that runs `tccutil reset Accessibility com.parla.app` + `tccutil reset Microphone com.parla.app` and relaunches, plus a dead-tap watchdog: if `AXIsProcessTrusted()` is true but the tap has produced no events since launch, escalate the current `NSLog`-only 3 s retry (`Hotkey.swift:126-129`) into a HUD error. Ref: Muesli `PermissionsManager`, macparakeet `hotkey_macos.rs:84-113`, openwhispr #14/#6. **Effort: M.**

13. **Onboarding: three-step, with a live tryout.** New `Sources/Parla/Onboarding.swift` gated on a `Settings.onboardingCompleted` flag — permissions (with ghost-pepper's drag-the-icon tile), model download, and a sandboxed dictation tryout whose output goes to the HUD, not the focused app. Today a fresh user gets a ⚠️ glyph and must discover the menu. Ref: macparakeet `UI/Onboarding/OnboardingFlowView.swift`, ghost-pepper `PermissionChecker.swift` `RunningAppDragTile`. **Effort: L.**

14. **Automatic dictionary learning.** New `Sources/ParlaCore/CorrectionLearner.swift` — after insertion, attach an `AXObserver` for `kAXValueChangedNotification` on the focused element for 30 s, diff the field against `insertText` with a word-level LCS, and propose a `Settings.dictionary` entry when a single ≤2-word substitution survives the guards (edit distance ≤0.65 normalized, ≥3 chars, not already in the dictionary, ≥2 occurrences in 7 days, 10-min cooldown, 3-dismissal cap). Parla's `Inserter` already reads `kAXValue` + cursor for `canEraseTyped`, so most of the AX plumbing exists. Ref: FluidVoice `AutomaticDictionaryCorrectionTracker`, TypeWhisper `AutomaticDictionaryLearningService`, ghost-pepper `PostPasteLearningCoordinator`. **Effort: L.**

**Explicitly not recommended:** multi-monitor rework (Parla's `activeScreen()` at `HUD.swift:385-395` already beats every implementation in the corpus — only add a `didChangeScreenParametersNotification` observer, S); Sparkle/auto-update (three separate repos shipped serious bugs from it — voicetypr #745/#782, VoiceInk #760 — and a browser link is the correct 0.1.0 position, though `CFBundleShortVersionString` in `scripts/make-app.sh` must start tracking real releases); settings search (6 pages doesn't need it).
