# Undo accidental capture cancellation (B57 experiment)

This experiment is off by default. Enable **Undo capture cancellation** in the Hub’s Data & Privacy page. An eligible ordinary physical keyboard, mouse or hands-free capture can offer **Undo** and **Discard** in the existing HUD for exactly three seconds after cancellation. A useful short mouse/key release can qualify. The usual disabled cancellation behavior is unchanged.

Undo creates a new local recognition operation and shows a temporary raw transcript in that HUD. **Copy** is explicit; it changes clipboard ownership. There is no automatic paste, field insertion, field Undo, Save, replay, transform, history entry or recovery item. A field change still yields only a preview. Discard clears the feature’s authority and retained content. Copy does not renew the preview deadline.

The whole capture must contain 6,400–160,000 finite mono Float32 samples at 16 kHz (0.4–10 seconds, at most 640,000 payload bytes), including pre-roll and converter drain. Elapsed capture through drain must also be at most ten seconds, with actual post-start PCM and finite RMS above 0.0001 plus the existing audio usefulness floor. Oversized, quiet, nonfinite, interrupted, reset or otherwise ineligible audio is refused in full, never truncated. This heuristic does not prove speech.

Permission and a strict safe security classification must exist at capture start and cancellation. Enabling later cannot authorize an older capture. Commands, presets, selected-text/spoken transforms, live typing, automation, tryout, microphone test, recovery/retry, pending discard, secure refusal, unacknowledged/no-PCM starts, device loss, sample cap, route/tap reset, ownership loss and internal preemption do not offer Undo. A new intentional start clears prior authority before preemption. Settings disable, invalid/load/save errors, observed secure or unclassifiable focus, expiry, Discard, quit and restart also revoke it. Canceled quit does not restore an old offer or job.

Only an explicit current HUD Undo consumes the offer. The frozen recognition request is bounded to a 4 KiB model path, 64-byte language, 128 dictionary entries and 16 KiB aggregate dictionary UTF-8. The frozen installed catalog model must have matching read-only verification metadata; missing, custom or unverified models are refused without hashing/cache writes, fallback, installation or download. A new recognition handle uses the existing serial native-work barrier, without the old streaming window or cleanup/snippets/replacements.

A consumed job has fifteen seconds from Undo to start ASR and thirty seconds to retain publication authority. These are cancellation/publication deadlines, **not** hard termination guarantees for native work. Queued audio can be released immediately. A running native call may retain its input and model until actual exit; later native work waits for that exit. A second canceled-audio offer is refused while a prior consumed job is queued or draining, while a new capture remains allowed. The raw preview is refused if empty or above 16 KiB UTF-8, and expires thirty seconds after publication. Audio ownership is released before preview publication. Capture diagnostics remain canceled; no B57 diagnostic schema or content logging is added.

The feature has no application-managed audio/text persistence path. Ordinary dictation may already have run shadow recognition, model preparation or configured provider warm-up before cancellation; revocation cannot undo a call already running. Transfer suspends recorder warmth until the next explicit entry, without changing the saved preference. Swift array sharing, earlier snapshots, native borrows and decoder temporaries can create physical copies. The audio/preview caps do not cap model memory or temporary native decoder output. No physical zeroization, OS swap/crash-image exclusion or force-quit erasure guarantee is made.

A single security/configuration monitor runs every 200 ms only while an offer, queued/running job or preview has authority, alongside boundary checks and finite deadline timers. It reads no field value/range, does not wake/prompt accessibility, and is absent when the feature is disabled. It cannot observe every transition between samples or while the main thread is blocked; it is not continuous proof of secure-focus exclusion.

Source/fake verification covers the real reducer cancellation drain, production executor, owned recorder/resampler, token-bound NSButton target callbacks, typed origin dispatcher, real PendingOperationQueue, RecognitionHandle with fake RecognitionClient, preview and explicit Copy. Ordinary-origin positive controls exercise the actual RecordingStore writer/remover and corpus path, history sink, provider pipeline and insertion/correction/result sinks before zero-entry/write checks for Undo. B25’s independent clipboard provider/snapshot/failure hold and termination reply semantics remain intact.

Native qualification remains pending: real AVAudioEngine quiescence and route changes; actual allocation/native lifetime and stop timing; strict security adapter evidence; HUD nonactivation, first mouse, docking/Spaces/full-screen/multiscreen and accessibility usability within three seconds; real recognition and B25 clipboard/quit compatibility. The experiment’s source configuration and fake tests do not qualify those behaviors. B24 field Undo is unavailable; B19 packaging/build permission remains a separate unanswered gate.
