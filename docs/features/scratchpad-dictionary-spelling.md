# Dictionary spelling in Scratchpad (B29, bounded source slice)

Off by default. In Parla's Scratchpad, save the **Dictionary spelling in Scratchpad** checkbox, focus the existing editor, then use **Dictionary spelling…** above it or in Edit. Select one whole word, or put the caret inside/at its end. Choose a displayed spelling explicitly, even when there is only one. Escape/outside click cancels. A focus change refuses the choice; the action never restores focus or searches for another occurrence. Ordinary macOS spellchecking remains available independently.

Only saved global Dictionary words participate. Matching uses `NFC(NFC(word).lowercased())`, with Unicode default lowercase. Output is the exact saved literal, including casing and canonical Unicode representation. `openai` can offer `OpenAI`; decomposed `café` can offer configured `café`. `opneai`, accent-stripped `cafe`, phrases, phonetic and acoustic alternatives are unsupported. Profiles, snippets and literal replacement rules do not generate suggestions. No learning, automatic winner, score, history, audio, external field, clipboard, paste or input-system route exists.

Saved order breaks ties. Canonically equivalent case-preserving duplicates keep their first literal. An exact UTF-16 no-op first representative is omitted, without manufacturing a suggestion from a later duplicate. At most five full literal outputs appear; additional distinct matches produce “first 5 shown.” No initial/default item or key equivalent is assigned. Native picker behavior still needs qualification.

The orthographic contract accepts complete composed clusters containing letters/decimal digits/connectors and attached marks, with at least one letter. ZWJ/ZWNJ is allowed only **within one composed cluster**, immediately after an attached mark and before a letter; it is never removed. Standalone marks/joiners, control/bidi/invisible/placeholder characters, mixed letter/emoji clusters, and apostrophe/hyphen/email/path/connected-dot fragments refuse. Ordinary surrounding punctuation and standalone emoji can delimit. Selected substrings/carets inside surrogate or combining clusters never round or expand. Raw UTF-16 is validated before bridging. Segmentation differences between supported OS versions remain a native gate; some short Indic words deliberately fail the grapheme minimum.

| Limit | Behavior |
| --- | --- |
| Word/output | 3–64 graphemes, ≤128 UTF-16 units, ≤256 UTF-8 bytes |
| Document | ≤65,536 UTF-16 units, queried before a snapshot |
| Range search | ≤129 UTF-16 units each direction, plus composed-cluster proof |
| Saved dictionary | ≤10,000 rows; larger stores refuse this action, without modifying the store |
| Candidate scan | First ≤257 UTF-8 bytes of every row, including invalid rows; ≤2,570,000 bytes total |
| Candidate work | 20 ms monotonic cooperative cutoff; complete scan required before presentation |
| Request | One, 30-second monotonic TTL; equality with deadline is expired |
| Retention | Original token + at most five outputs, finite IDs/ranges/revisions/signature; no retained document/vocabulary/history |
| Settings I/O | Strict fresh regular-file max+1 read, ≤1 MiB; no recovered settings or mtime/size cache authority |

The time cutoff covers candidate work, not disk/native-callback wall time. Candidate content has a 1 MiB logical transient budget; existing store/view content and framework/allocator overhead are separate from that budget. This is not a measured RSS claim. Configuration signatures cover only the Boolean, ordered dictionary and relevant snippets/rules, never credentials or the whole settings object. Fresh reads at begin and choice detect same-size/timestamp rewrites. Store notifications and Hub draft callbacks invalidate metadata without tokenization. Constructor, disabled action and cached UI/menu validation do no editor-selection/snapshot/candidate work.

The checkbox uses a dedicated raw JSON Boolean patch under the SettingsStore lock. It preserves unknown fields and legacy values/endpoint bindings, checks the expected flag and original bytes before atomic write, and never migrates credentials or refreshes Hub/setup/mic/provider state. Failed disable still revokes immediately and leaves this owner disabled until explicit successful recovery. Missing settings use credential-free defaults; corrupt/recovered/nonregular/oversized/stale/faulted settings refuse. Same-process locking plus byte comparison is **not** cross-process compare-and-swap. Existing full writers preserve the authoritative flag; Hub adopts only that field in draft/base and retains its existing privacy conflict guard and general/mixed callbacks.

The receipt binds this controller, document/view/storage/window/visible session, request/candidate set, policy/config signature, edit/selection/config revisions, range/selection/affinity, exact original UTF-16 and monotonic deadline. Choice consumes before callbacks, checks strict owned key-window/first-responder focus, and repeats full freshness checks after `shouldChangeText`. Typing/storage changes, caret away/back, Undo/Redo, vocabulary/rules/snippet drafts, save/import/errors, disable, reload, close/hide/miniaturize/resign, quit intent (including canceled quit), expiry and a new action revoke. No automatic regeneration occurs.

Production and fake-port tests use the same controller transaction. The native adapter pins the **same NSTextView.undoManager**, breaks typing coalescing, balances its own group and temporary implicit-registration suppression, calls shouldChange once, performs one owned replace and selection update, then didChange once and registers one bounded reciprocal inverse on that manager. Nested admission is limited to the exact authorized delegate call. Undo/Redo restores the exact before/after literal and selection/affinity; accepted edits remain undoable with suggestions disabled or expired. Document reload invalidates inverse authority and clears document Undo. Unexpected observer state revokes and reports a qualification failure; there is no second repair replacement. Separate text/selection APIs and notification batching are not an atomic transaction proof.

Scratchpad text continues to persist in `Application Support/Parla/scratchpad.txt`: existing 0.5-second current-value debounce, close flush and quit ordering. A stale/refused choice does not cancel a typing save. No candidate snapshot is persisted; ignored persistence-error behavior is unchanged. A never-shown owner constructs no native editor/window and does no Scratchpad file I/O on quit.

B29 remains **PARTIAL**. Model-free tests prove policy, controller/receipt decisions, fake native-owner protocol, save scheduling and settings/Hub behavior. They do not qualify actual native focus/menu default-selection behavior, real Undo/coalescing/notification timing, text/caret atomicity, supported old/current macOS Unicode/RTL rendering, IME, accessibility or human candidate quality. No native UI was run for this slice. External replacement remains gated on B08/B24; acoustic/confidence/fuzzy work requires a separate contract and real metadata/calibration.
