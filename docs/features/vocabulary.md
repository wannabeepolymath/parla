# Vocabulary, literal replacements, and JSON transfer

Hub → Dictionary contains the word priority arrows, literal replacement editor and preview, and Import/Export controls. Snippets remain under Hub → Snippets.

Words are spelling hints, never automatic replacements. Saved row order determines priority. Prompt selection collapses whitespace and ignores case-insensitive duplicates, blank entries, and individual hints over 256 UTF-8 bytes. It selects whole hints in saved order, fitting later smaller entries when an earlier entry does not fit. The dictionary portion is bounded to 2,048 UTF-8 bytes for all ASR paths (including commands and streaming) and 8,192 bytes for cleanup and selected-text commands. Streaming additionally retains the latest 200 characters of confirmed context, bounded to 800 UTF-8 bytes; the separating space costs one byte. These are byte limits, not token estimates. Saved words are not removed when omitted. Hub shows selected counts, and refuses newly edited oversized hints with a save error; legacy oversized entries remain saved. Priority is manual and global; app-specific profiles are outside this slice.

Literal replacements default to an empty list (off). Matching is case-sensitive and uses Unicode letters, numbers, combining marks, and connector punctuation as word constituents. A source beginning/ending in punctuation needs no word boundary at that end. Scan original text left to right; the longest source at each position wins, with row order breaking equal-length ties. Output is appended literally, including dollars, backslashes, and newlines, and is never scanned again. There is no fuzzy or numeral-normalized matching. Rules run once after provider cleanup or its raw fallback. With no provider configured, the dictation reducer runs them locally before delivery. Selected-text command results bypass these dictation rules.

Whole-utterance snippets use the existing spoken-trigger normalization and bypass both the provider and replacements. Equal-length normalized trigger ties now resolve by lexical trigger order. Expansions stay literal, including wrapping quotes and whitespace. Destination rules still flatten newlines in terminals, chat, and single-line fields. Secure-field and stale asynchronous delivery guards remain in the existing reducer. History retains the original transcript and, when changed, the final local result, including on provider failure.

Transfer uses exactly these required JSON fields: `format: "parla-vocabulary"`, `version: 1`, `words: [String]`, `snippets: {trigger: expansion}`, and `replacements: [{source, replacement}]`. It never serializes Settings. Unknown top-level/replacement fields, unsupported versions, invalid JSON, blank hints/triggers, oversized hints, duplicate replacement sources, documents over 1 MiB, over 10,000 total entries, or outputs over 65,536 UTF-8 bytes are rejected before changes. Incoming duplicate words are normalized and counted in the preview. Conflicting keys are listed. Merge keeps existing values and word order; replace requires an explicit confirmation and refuses an empty document.

Replace must successfully write a vocabulary-only JSON backup into `vocabulary-backups/` next to settings.json before saving. Backup and save errors are reported in the Hub. Unrelated settings (including credentials, endpoints, models, and hotkeys) come from the latest settings file. Preview application re-reads vocabulary under the store lock and refuses newer vocabulary edits; any Hub edit or refresh invalidates its preview. Import/export flush the existing save debounce and refuse load/save errors. Export refuses the active settings.json path.

Verification uses isolated temporary stores, fake credentials, injected cleanup closures, and reducer effects. No model, microphone, provider request, browser, or actual user settings are required. Native UI appearance was not manually exercised.
