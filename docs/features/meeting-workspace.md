# Meeting workspace

## 0.7.0 source candidate — 2026-11-07

Production composition now enables explicit meeting capture. Nothing starts recording on launch, page entry, permission grant, source refresh, restart or quit cancellation. Startup loads saved metadata and sweeps retention only. The existing single retained meeting slot remains. Copy any text you want to retain, then Delete the saved meeting before starting another. Keep retains that slot and its remaining files until you delete it; it does not restore audio already deleted.

Choose the microphone in Settings and optionally refresh/select one running application in Meetings. Press Start, acknowledge **“Everyone in this meeting knows it's being recorded”**, then confirm Start recording. The acknowledgment is single-use and bound to the current page, owner and source revision. Declining, changing sources or leaving the page revokes it. Microphone permission refusal explains System Settings; a grant requires a fresh Start and acknowledgment. The application backend is the existing macOS 14.2+ private Core Audio process tap, restricted to one frozen process incarnation and one output route. It records audio only, with no screen video, whole-system mix, helper-process grouping or process restoration. macOS owns the System Audio Recording prompt during native start. The bundle declares its audio-capture purpose, and Meetings exposes the corresponding privacy settings link. Native denial/loss stops the take and preserves any saved prefix without claiming that a native start proves authorization. Prompt appearance, signing/TCC and older-OS behavior still require hardware qualification.

Microphone and application audio use independent bounded canonical ingresses, precharged before either starts, with a shared serialized storage writer. Stop, page/window close, expiry and the existing quit/restart/updater coordinator fence both sources and retain their actual tasks through callback, converter and writer exit. A persistent action-rail indicator and a red menu-bar recording indicator remain active while capture is owned, including unavailable/uncertain retirement. There is no automatic restart. Source labels identify capture tracks, not speakers. Timing remains unknown unless independently established; no synchronization, echo cancellation or diarization claim follows.

Transcribe saved audio is a separate explicit action, using the configured local recognition engine on this Mac. Meeting raw text is not uploaded, inserted, copied automatically, added to Scratchpad or added to dictation History. The meeting composition supplies no History sink; recognition remains raw-only. Optional provider cleanup/summary has no meeting action in this candidate, so no configured provider is called. Users can explicitly open/copy the saved transcript.

The proposed policy remains pending final user sign-off. Its nanosecond durations are named in `MeetingSession.RecordingPolicy`, and the UI notice derives its durations from these same constants: successful raw audio **24 hours after all saved transcribable chunks are accepted**, failed/canceled/untranscribed audio **7 days from session creation**, transcripts **30 days from session creation**. Too-short chunks do not prevent completion of otherwise successful transcription. Each stopped meeting has Keep and Delete controls. Keep suspends both expiries until removed; removing Keep restores the original deadlines, with overdue deletion evaluated immediately. Explicit Delete also deletes a kept meeting. Expiry is checked on startup, explicit review/actions and registered deadlines while Parla runs; no physical deadline is promised while the app is closed or resources remain held.

Raw expiry uses a durable per-source deletion intent, then exact-member unlink and a separate completion publication. The transcript, provenance and source metadata remain after audio deletion, and deleted audio cannot be retranscribed. Whole-meeting expiry and explicit Delete reuse the existing durable deletion/coordinator path. Existing pre-policy seven-day ledgers remain readable under their original policy; they are not silently rewritten into the new retention contract. Meeting directories/files remain private (0700/0600), local-only and marked excluded from backup using the directory descriptor. This is a backup-exclusion request, not an encryption or physical-erasure claim; external copies and backup programs that ignore OS exclusions are outside this store.

The B43 v2 recovery correction handles four reproduced release blockers. A refused app-audio tap returning no object now retires its producer so Stop and Quit can finish; a possible returned handle still holds shutdown until cleanup is known. Raw deletion recognizes both accepted names of a source whose rename preceded its ledger publication. Transcript expiry takes priority over an interrupted raw-audio deletion and removes the entire meeting. At startup, Parla discards a private `manifest.next` only after validating the committed manifest, owner and remaining namespace. Unknown contents still refuse recovery. If the committed manifest cannot be read, Meetings offers an explicit, confirmed **Delete all meeting data** action: it locks and validates the private meeting namespace, preflights every regular-file identity, refuses unknown/unsafe members and removes only meeting files in bounded steps. It never adopts the unpublished metadata.

The source checks and fail-without-fix evidence are recorded in [B43 source verification](../qualification/macos/2026-11-07-b43-source-verification.md). These tests use synthetic audio and injected capture/recognition services. No real microphone/application capture or live provider ran. Native permission/UI behavior, actual process/route and converter behavior, drift, echo, long-session coverage/partial gaps, installed recognition, real crash/recovery and storage-policy acceptance remain open. B43 is **needs qualification**, not complete; policy sign-off remains a release gate.
