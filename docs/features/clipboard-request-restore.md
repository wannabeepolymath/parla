# Observable clipboard data-request restore experiment (B25 / wave 3H)

This is a default-off source experiment, selected by the separate global
`clipboardReceiptRestoreEnabled` preference in Hub Privacy. Missing/null is off;
malformed values invalidate configuration. A fresh valid app configuration is
consulted for each ordinary or stored/history insertion. The core Inserter and
insertion-check CLI default to the fixed policy; core never loads Settings.
Result-only automation never enters clipboard delivery.

The default remains eager text publication with the existing markers/source,
restored after a requested 0.8 seconds. The six existing known remote identifiers
always retain the fixed 5-second path, including when opted in. AX replacement,
Unicode events, text shaping, capture authority and correction learning retain
their existing contracts. This does not provide Undo or Restore Raw.

## What is observed

Opt-in local delivery publishes only string as an explicitly promised type.
Transient, concealed, autogenerated and source representations remain eager.
A retained provider synchronously fulfills its own string item from immutable
prepared UTF-8 bytes. Entry phase/time and in-flight activity are serialized in
a short scalar mailbox lock; AppKit setters, posting, notifications, diagnostic
updates and app actions run outside it. The clock port is a primitive monotonic
read. A coalesced scalar notification returns to main asynchronously, with no
main-queue sync, worker waiting or polling. A timer drains the same mailbox
before deciding; entered fulfillment prevents restoration until completion.
A logical close prevents new fulfillment while fresh restore items are prepared.

Only successful supported-item requests entering after the complete Cmd-V pair
and still matching the transaction token and board count can establish observable
receipt evidence. Preparation/publication, willPost, inside the event pair,
wrong item/type, nil/wrong board, old transaction and settling callbacks cannot.
No own promised-text readback is used. Callback duplication is supported; cached
reads may generate no callback. Provider-finished is advisory, never ownership
loss or insertion proof. A reader may be a clipboard manager. No target identity,
read census, accepted badge or automatic insertion retry is inferred.

The existing Original hook runs once after clipboard preparation, immediately
before the event pair, and never runs from a provider or timer. Late callbacks
cannot create an Original offer or extend its lifetime. Explicit Copy Original
is a new clipboard owner, preserved just like any user/manager copy.

## Timing, preservation and refusal

Proposed local policy (not measurements): 0.8-second floor after injection,
0.3-second quiet interval after the last eligible request, and a nonextendable
requested maximum of 8 seconds after publication. Without eligible callbacks,
wait to maximum. Otherwise request the earlier of maximum and the later of
floor/last-request-plus-quiet. There is one maximum and at most one active quiet
timer, with cancellation and token/generation checks. A main-loop, setter or IPC
stall can overrun any requested deadline; 8 seconds is not a wall-clock guarantee.
Quiet means only no recent observed provider demand, never all readers finished.

Before mutation, snapshot every item/type/data and verify a stable count. Opt-in
refuses denied, nil, unreadable, mutating or over-cap snapshots, text/preparation/
registration/setter failures. Caps: 8 MiB aggregate old Data; 1 MiB prepared UTF-8;
256 items; 1024 representations; 64 KiB aggregate UTF-8 type names. Aggregation
uses subtraction checks to avoid overflow. There is no truncation, text/image
subset, or implicit uncapped fallback. Reading one external representation can
allocate unbounded transient data or stall before its size is known. Caps bound
retained application data, not total RSS, server copies or secure zeroization.

One token+count lease owns the snapshot/provider/published item. Reentrant paste
while preparing/posting/settling refuses. A second paste first restores the old
snapshot or respects a new external owner, then snapshots that actual clipboard.
Restoration prepares fresh items before the final count check, preserving every
representation. Count check + write is not an interprocess compare-and-swap;
another process can race that narrow gap.

False/partial publication gets at most one rollback while the clear count is
still owned, with no event pair. Setter/write failure is never reported restored.
Failed owned rollback/restore retains the bounded original in a pending failed
settlement, refuses a second paste and blocks safe restart. It does not silently
snapshot temporary text or retry insertion/restoration. A subsequent external
copy can release the hold. The menu reports the unresolved restore without
content. This failure hold bounds bytes, not lifetime; it can outlive 8 seconds.

## Lifecycle and diagnostics

Disable/invalid settings, new capture, cancel, operation finish, Original clear
and diagnostics Clear prevent neither fulfillment nor the existing latched
lease's settlement. Graceful quit stops new publication and keeps the run loop
and provider alive until settlement. AppDelegate's combined termination owner
waits for both updater cleanup and clipboard settlement, with one final reply.
A failed owned restore cancels quit with a content-free explanation, releasing
only termination intent. The original and updater safety barrier remain owned.
`claimRestartIfSafe` still checks every pending/failed clipboard lease. Crash,
force kill and pasteboard-server failure cannot guarantee preservation.

Optional typed `DiagnosticClipboard` is an additive schema-v1 field: older
records missing it decode to nil and older readers can ignore it. Finite enums
and bounded numeric policy/timing/count fields contain no transcript, snapshot,
UTI, bundle ID, reader identity, endpoint or free-form error. Receipt evidence
never promotes `postedUnverified`. Late updates use the real DiagnosticOperation
handle even after finish, and cannot revive a cleared/evicted record. Stored
paste's nil handle is deliberate. Hub export writes the exact frozen reviewed
bytes; a late update changes only a newly prepared review.

Fake production-entry tests qualify source policy and wiring only. AppKit
promised writing options, callback thread/reentrancy, caching, native item
safety, graceful quit availability, actual busy/slow apps, Chromium, managers and
remote environments remain unqualified. No measured latency or reliability
improvement, native acceptance proof, or completed B25 qualification is claimed.
