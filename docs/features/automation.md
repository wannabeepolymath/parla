# Automation source and experimental static packaging preview (B19 / wave 3D.3.1)

This is a production-wired **source preview**, off by default, with an opt-in **experimental static packaging preview**. Four in-app AppIntent wrappers, a result entity/query and a trusted build-once metadata producer are implemented. Working packaged Shortcuts actions have **not** been qualified. Static compiler output, extraction and ad-hoc seals are separate from discovery and native runtime qualification. B19 stays **PARTIAL / runtime unqualified**. No URL bridge, service, second recorder or additional inference queue is introduced.

Enable automation and Clear Last Result live in Hub → Data & Privacy. Automation is ordinary raw or cleanup dictation with global recognition/output settings. Selected-preset mode is explicitly unsupported in this slice. Delivery is always result-only: no paste, clipboard copy, field replacement, live field typing, correction watcher or focus action. Missing Accessibility can permit result-only; known secure input/field evidence refuses capture, result and history. Missing mic permission or a requested model without cached installed catalog verification refuses Start without prompting or downloading. Custom model paths are not accepted by this first automation capability gate.

`AutomationRuntime` resolves the typed main-actor broker without constructing AppDelegate, Hub or a recorder. The real delegate registers `DictationInvocationHost` through `ApplicationStartupCoordinator.bootstrap()`. The same host admits current hotkey starts/stops/cancels and automation. Accepted reducer effects bind the real operation before recorder start can synchronously fail. Keyboard starts, selected presets and tryout may preempt automation; old automation handles cannot stop a newer capture. The existing keyboard Accessibility, selection, modifier and target-at-landing policies remain. Old keyboard raw/history behavior remains separate from automation eligibility.

Start retry keys are typed, process-scoped monotonically issued IDs, distinct from session handles and reducer operation IDs/generations. Retrying a live request joins its acknowledgement. Completed retry records never restart capture. A high-water mark refuses old requests after bounded terminal records expire or are evicted; requests issued out of order may be refused as stale. Stop/Cancel require the returned session handle. Unknown/cold handles cannot arm future actions. There are at most eight live waiters and sixteen text-free terminal records, expiring after sixty seconds. Host/capture acknowledgement has a five-second deadline; Stop completion has thirty seconds. These are application bounds, not promises about native Shortcuts execution budgets. Deadlines use an injected monotonic scheduler, without polling or waiting for a canceled native child to exit.

Cancellation revokes the retained B50 operation before releasing waiters or requesting abort. Matching capture uses capture cancel; pending work uses retained token authority even if the menu now points elsewhere. Owned audio disposal and the existing actual-exit barrier remain in force. Retry, recovery, playback and download operations do not share this cancellation scope. A completed result or already attempted delivery cannot be undone.

The RAM slot receives only the reducer's single final adjudication, after ownership/security checks, independently of whether History is enabled or can save. Cleanup/local fallback is labeled as such. Nil, empty, unavailable, minimum-duration and oversized results fail explicitly. No intermediate raw/provider output is exposed. One eligible final string of at most 64 KiB UTF-8 lives for an absolute five-minute monotonic lifetime; reading never extends it. The slot stores operation identity and outcome, with no raw/audio/field extras. Get Last reads only this current-process slot, without saved-history fallback or model/provider/clipboard work. Caller-held strings cannot be retracted, and logical RAM clearing is not physical memory erasure.

New accepted captures, cancellation/discard, secure refusal, clear, Clear History, disable and quit invalidate retrieval. An eligibility epoch prevents a held completion from repopulating a cleared slot. Clearing retrieval does not cancel ordinary keyboard insertion/history. Both menu and Hub Clear History use the same invalidation callback, even if durable history deletion fails. Ordinary history/audio policies still apply; result-only is not a disk-free recording claim. Broker/status/diagnostic records contain no transcript text. The automation Pipeline uses content-free provider failure logs so echoed response/error bodies cannot become automation log content; the existing keyboard logging policy is unchanged.

All launches now register passively. There is no demonstrated intent-specific launch discriminator, so launch no longer prompts for permissions, opens setup automatically, migrates secrets, constructs/warms a model or warms the microphone. Explicit Open Parla/Finder reopen/setup retains model setup and warm-mic preference; explicit dictation retains credential migration and warm-mic entry, with recognition acquisition on the existing serial queue. Existing permission buttons and model selection remain reachable. Onboarding can advance using an installed model while it is deliberately unloaded. Tryout retains admission through recognition exit. Explicit setup/model selection waits for prior native work before loading; the updater and keyboard output remain available. Deferred warming changes first-use latency and initial-window behavior; native startup/UX timing remains unqualified.

Injected tests exercise the real runtime/broker, host, startup coordinator, reducer, Pipeline, PendingOperationQueue, result store and history/clear boundaries. They use inert clocks, permissions, recorder/recognizer/provider sinks and isolated temporary stores, not AppDelegate/Hub launch or native capture/field/event/clipboard operations. The broader existing suite includes read-only permission/AX status checks; those are not native capture or delivery qualification.


The native source actions are Start Parla Dictation, Stop Parla Dictation, Cancel Parla Dictation and Get Last Parla Result. Each uses local device authentication and the baseline foreground `openAppWhenRun = true` property. The source retains macOS 13.3; it uses neither unguarded `supportedModes` (26+) nor `isDiscoverable` (14+). Foreground activation does not preserve a text destination. AppIntents source/test compilation does not prove old-OS loading, authentication, native execution budgets, discovery or Text extraction in Shortcuts.

Start returns an opaque control String. Wire that exact value into Stop/Cancel's required Control Session parameter. Its canonical grammar is `parla-control:1:<lowercase process UUID>:<lowercase session UUID>` with no other fields, whitespace or payloads. Unknown or prior-process handles refuse; handles are identities, not secrets or authorization. A repeated Start joins the current automation reservation, including readiness/stopping, with the existing broker-issued retry key. After terminal completion a new explicit Start gets a new request. There is no OS-wide replay or exactly-once claim. Stop/Get Last return `ParlaAutomationResultEntity` with Text, Outcome (`final`/`localFallback`) and a distinct opaque operation ID (`parla-result:1:<process UUID>:<operation UUID>`). Entity display text is always “Parla Result”, never a transcript excerpt. Cancel returns only a fixed status String. Errors contain fixed parse/broker categories, without input/provider/native error descriptions.

All four actual main-actor perform methods resolve the existing app-owned runtime; the real AppDelegate's passive registration is consumed unchanged. Task-scoped resolver injection permits inert tests without touching default settings. Constructors, provider metadata and empty suggestions resolve no runtime. Entity queries resolve only explicitly requested canonical IDs matching the enabled, nonsecure, nonexpired current RAM slot; they never enumerate history. Invalid/empty requests return no entity without resolving services. Stop revalidates the current slot after its async broker call; no further suspension is added before returning text. Already returned caller text cannot be revoked. Returned values never become B11 posted/AX-confirmed delivery evidence.

## Experimental static metadata packaging

`PARLA_NATIVE_INTENTS=0` remains the default. That path retains the existing host ad-hoc build and Developer ID ⇒ universal build policy, and explicitly reports omitted metadata. Native-enabled failures never fall back to it. Release callers still use their existing default paths and signing policy; the experimental isolated bundle is not automatically handed to make-dmg/notarization.

To build an isolated static preview, choose a **new absolute path with an existing canonical parent** (on macOS `/tmp` normally resolves to `/private/tmp`):

```sh
PARLA_NATIVE_INTENTS=1 \
PARLA_NATIVE_OUTPUT_ROOT=/private/tmp/parla-native-preview-UNIQUE \
PARLA_NATIVE_ARCHITECTURES=host \
scripts/make-app.sh
```

Use `PARLA_NATIVE_ARCHITECTURES=universal` for an arm64+x86_64 ad-hoc preview, independent of signing identity. A supplied `PARLA_SIGN_IDENTITY` still forces universal and retains framework-first/app-last `--timestamp --options runtime` signing, with the existing app entitlements. That Developer ID branch is not qualified by local ad-hoc checks. Local native previews use `--timestamp=none`, the existing bundle identifier/designated requirement, and no identity lookup. The default-off signing behavior is retained.

The native branch executes `scripts/build-app-intents.py --package` directly and consumes its exact binary/receipt in process. It accepts no externally generated `PARLA_APPINTENTS_INPUTS`; unset that old opt-in variable. JSON/path strings are never shell-evaluated. Existing output roots (including empty directories or symlinks) refuse. Builds, logs and receipt inputs remain inside the new owned root; assembly uses its own stage. Extraction/copy/rpath/signature/input failure prevents successful publication. Only the attempt-owned stage is removed on failure. Unknown root `Parla.app`, distribution artifacts and shared `.build` are preserved. Successful promotion uses an exclusive rename to `<output-root>/Parla.app`; no bundle bytes are written after app signing.

The narrow producer uses the demonstrated **native SwiftPM backend**, one release `--product Parla --arch ARCH` build per architecture in separate fresh scratch roots, jobs 2 and frontend threads 2. `--show-bin-path` is a path query, not another compilation. It supplies boolean `-emit-const-values` and the compiler-format protocol array derived from the selected toolchain's `SwiftConstantValues/AppIntents.json` `constValueProtocols`. It never sets a shared/global supplementary output path, replays compiler commands, reuses old empty constants or builds a reduced intent-only target. Current dependencies are local/vendored; automatic resolution is disabled. No download, dependency upgrade, backend, target, deployment or entitlement change is part of this route. SwiftPM may print its existing `--skip-update` deprecation warning.

Each actual verbose driver/frontend command, generated source list and output map must agree with the complete current Parla/ParlaCore source sets and the selected SDK/13.3 target. The current full Parla module has 44 sources; membership is derived, not hardcoded. Exactly seven nonempty compiler declarations are required: the four intents, provider, result entity and query. Dependency ParlaCore's empty constants are accepted only as that dependency, never as Parla's replacement. A metadata-bearing dependency or changed dependency graph refuses as unsupported. Dependency/static-metadata lists are explicitly empty for the current package. Universal mode builds each thin slice once, lipos the final executable, then extracts **once** with both architecture input sets; metadata JSON is never lipo-ed.

The producer freezes membership, SHA-256, mode and modification time for Package files, all Sources, vendored Frameworks, Resources, producer/adapter/packager scripts, selected toolchain/SDK/platform build libraries and selected executables. Directory symlinks are recorded without traversal; source symlinks refuse. Actual generated source/output maps, thin binaries, constants, protocol arrays, link dependency information and invocation logs are retained and rechecked. A receipt is written only after the owned actual invocation succeeds and its complete inputs still agree. Actual argv/PID/exit/start/end logs live under `commands/`; failed invocations leave evidence without a success receipt. Source additions/removals and source/package/resource/tool/SDK/output changes refuse before receipt or publication. There is no public test-runner/validation-bypass environment variable or CLI option.

The producer's schema-1 receipt records module `Parla`, deployment `13.3`, actual build interval, immutable final binary, exact ordered sources, selected processor/compiler/toolchain/SDK/Xcode/discovery identities, full input inventory, selected tools and per-architecture source/constant/link inputs plus actual invocation/generated-output proof. File records use absolute paths and SHA-256. Pure Mach-O reads check actual executable slices, macOS platform and 13.3 minimum. Constants/link files/binary must belong to the actual interval and appear in constant→link→binary order. Future intervals or intervals older than one hour refuse; expiration requires a new build, never timestamp refresh. The signed/rpath-adjusted app copy has a separate hash; the receipt binary is unchanged and retained for review.

`scripts/app-intents-metadata.py` remains an explicit-input **validator**, available with `--inputs --binary --resources --source-root --architectures`. A caller-written receipt alone is not compiler provenance and cannot bypass the production packager's producer. It validates current sources, tool identities, architectures, declarations, timestamps and list membership before invoking the exact processor. After extraction and copy it rechecks input identities/source membership and verifies byte-for-byte resource equality, with collision refusal and partial-copy rollback.

The **only supported observed static output contract** is Xcode build `17F113`, processor SHA-256 `e7122197c7960c363ead21eef931017eba3c992473625964cdfdeff584c4c2d0`, and metadata schema `3.0`. Unknown tool/schema/version combinations fail closed without speculative flag fallback. Nonempty `Metadata.appintents/extract.actionsdata` and `version.json` are required. Structured validation checks exact four action identifiers/qualified/mangled types, foreground/auth-policy markers, parameter/result types, shortcut/provider identities and phrase/action references, result entity Text/Outcome property types and default-query/result references. Duplicate JSON keys refuse. This validates the retained static serialization, not execution of those policies or results.

For **this known static preview only**, `objects.appintentsmanifest` may be absent, matching retained actual processor output. Installed/upstream xcspec still lists it: its discovery semantics remain an explicit unresolved gate. A present manifest must be owned, a regular nonsymlink and nonempty; its opaque tool-owned format is not invented or parsed here. No empty/fake manifest is manufactured. All actual generated metadata, localizations and other resources are copied unchanged beneath `Contents/Resources`; output symlinks/unowned/special files refuse. A single owned architecture-neutral auxiliary stringsdata output is requested, outside installable resources and immutable compiler inputs. It is not copied as an app translation.

Metadata/resources/plist/rpath are final before framework-first/app-last signing. The producer's complete input freeze is checked around extraction/copy/signing/promotion. Actual signed bundle bytes, plist/resources, strict/deep/all-architecture signatures and executable headers are checked before exclusive promotion. Static seals do not qualify Shortcuts discovery/registration, cold/already-running app ownership, foreground/local-device authentication, execution budgets, Start→Stop Text/entity query, cancellation/preemption/readiness/permissions/security/expiry/clear/history-off/keyboard behavior, native Intel or old-OS loading, FoundationModels availability/assets/offline/provider behavior or human quality, or Developer ID/notarization/release distribution. AppIntents is actually **strong-loaded** and FoundationModels **weak-loaded** in the retained actual slices. Compiler SDK 26.5 identity is distinct from the executable's literal SDK load-command stamp; neither proves macOS 13.3 launch.

Fast checks use self-cleaning **SYNTHETIC** fixtures, never real metadata or signer output:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/tests -p 'test_*app_intents*.py' -v
bash -n scripts/make-app.sh
```

Adapter tests exercise the actual validation/install functions. Producer/packager tests exercise the actual entry with fake bottom command execution and selected-tool resolution, including host arm64/x86_64/universal, build-once/path-query distinction, actual-command/source/map matching, full resource copy, receipt/input mutation/expiration refusals, output collisions and build/extract/copy/sign/seal failure rollback. Shell entry fixtures run only owned copies with inert command spies: default-off performs no producer/extraction; native exec has no second build/fallback. Developer ID preservation is checked only through source/arguments, without certificates. These fixtures are distinct from explicitly authorized fresh full-module native host/universal build/extract/ad-hoc-sign smoke checks; neither category establishes runtime discovery/support.
