# macOS microphone self-test (B55)

Open **Microphone Test** in the Hub, or use the link on the first onboarding permission step. Start is explicit and requires already-granted Microphone access. The page never requests permission automatically; Start can direct you to General/System Settings. No ASR model, cleanup provider, credentials, downloads, history, recording store, insertion or clipboard path is involved.

The test uses the app's shared `AudioRecorder` in cold diagnostic mode. Start closes any idle warm engine, drops its pre-roll and converter state, then opens the selected input. Capture is limited to 10 seconds and 160,000 converted 16 kHz mono samples; oversized chunks and the converter tail are truncated at that ceiling. A 10 Hz control-thread poll reads scalar facts, with a two-second first-PCM deadline. The callback converts and accumulates bounded audio/scalars only, without UI dispatch, logging, JSON events or disk work. Engine epochs reject queued taps and configuration notifications after close/restart.

The status distinguishes waiting, PCM with signal, silent PCM, conversion failure (including invalid nonfinite PCM), no first PCM by the deadline, early Stop with unknown signal, start failure and a lost route. RMS is amplitude, never a quality, SNR, clipping or device-ranking claim. A signal status means signal occurred during this test. Device labels come from the actual input audio unit, with unknown evidence and requested-route mismatch/fallback shown explicitly. The requested UID is not routing proof. Labels and identifiers stay local in RAM and never enter B11 export, settings or logs. Existing operation-owned scalar B11 route/first-PCM facts remain separate.

**Stop closes the input engine** and discards recorder-owned audio/pre-roll/converter storage after transferring the sole bounded review buffer to the Hub controller. The controller keeps this buffer for explicit **Listen**; Stop does not promise to destroy audio needed for review. Listen lazily creates an in-memory player tagged 16 kHz mono. It never writes a WAV or opens live loopback. Stop Listening drops the player and its scheduled PCM; the controller's bounded review buffer remains until Clear, a new test, page leave, Hub window close/resign, application resign or quit. Canceled timers and late native/playback callbacks cannot restore it. Swift logical ownership/disposal is not a secure physical-memory erasure guarantee.

A token-owned capture admission is held through capture, stopped review and Listen. Clear/leave returns to dictation. Test Start refuses existing dictation, automation, tryout and shortcut capture; keyboard/automation/tryout/shortcut starts refuse while the diagnostic lease exists. Ordinary keyboard replacement and keyboard/tryout preemption of automation preserve their existing semantics on the same physical recorder. Independent hotkey suspension tokens prevent one owner from unsuspending another. The physical recorder's ordinary lease lasts through actual stop; diagnostic cleanup closes capture before releasing its review lease. Old diagnostic stop/clear callbacks cannot stop a later ordinary capture.

Recovery playback is independent. Starting or listening to a test refuses while recovery playback is active; recovery Play refuses while the test/review owns admission. Neither action cancels, deletes or releases the unrelated recovery operation/file. No policy is added for unrelated system audio; use headphones for explicit local Listen.

The saved `warmMic` preference is never changed. Runtime warmth is temporarily suspended from diagnostic Start through Clear/close, including settings saves during this interval. Closing a diagnostic never implicitly rewarms the microphone. The next explicit setup/dictation entry restores the latest saved preference; ordinary capture/stop then follows existing warm/Bluetooth/pre-roll behavior. This avoids immediately recording unowned test-adjacent pre-roll after Stop or close.

Canonical macOS B55 diagnostic behavior is accepted. All 23 Hub and 20 owned-workbench methods passed in the current recorded broad run. Model-free tests drive actual Hub commands, the production recorder adapter and conversion path with injected engine/route, deadline clock and player, plus the actual invocation host/reducer with fake effect sinks. These tests construct no default native input engine or output player; compilation alone is not native proof.

A separate supervised owned workbench exercised the production Core recorder adapter and player: one six-second signal run, explicit Listen, a known route, and cleared recorder/pre-roll/converter counts. The user confirmed hearing that recording afterward in a separate hash-bound addendum. This demonstrates one current-host capture/listening interaction, not a native production-Hub UI run or calibrated device comparison. The broader Hub can perform unrelated settings/status work; the microphone command itself has no model/provider/persistence dependency.

Native production-Hub event/rendering behavior, route/permission transitions, all hardware sample rates, disconnect/fallback failures, headphone configurations, microphone indicator behavior and forensic memory erasure remain unqualified. Android comparison is optional and outside the current macOS-only scope; no device winner or quality/calibration claim is made.
