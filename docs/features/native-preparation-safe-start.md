# Native preparation Safe Start (partial B53)

Default **off**. This opt-in experiment supports the three verified, app-owned Whisper catalog models on known arm64/x86_64 loaded builds. It tracks native context construction, **explicit synthetic setup warmup**, and the **first eligible real-audio recognition request on each native instance**. A request can include several native calls, including automatic language probing/retry. It does not isolate hidden preparation, an exact individual C call, or acoustic effects, and does not diagnose GPU faults. Optional backends, whole B53, native/human qualification and packaging remain unqualified. There is no automatic CPU fallback, model substitution, extra warmup on ordinary recognition or canceled-capture Undo, or privacy-setting migration.

## The adopted uncertainty policy

After two consecutive **unresolved journal records** for the exact model/build/primary resource role/phase, automatic preparation pauses. They are unknown outcomes, not confirmed native crashes, interruption strikes, forced kills, or GPU evidence. A record is committed just before native entry; death between commitment and entry can leave one too.

A known current-process persistence failure makes tracking unavailable and refuses further protected preparation. A single bounded durable quarantine is attempted after a failed retirement or consumption. If successful it prevents counting that known fault and requires explicit reset. But if native returns and **all** terminal/quarantine writes fail before process death, the next launch sees the same pending bytes as death inside native code. Under this explicitly weaker policy that unknown record **may count**. This is mathematically unobservable from that journal, not solved by fsync, two files, or passing tests. No strict no-false-native-strike guarantee is made.

Normal return (including empty native success), returned error, cancellation, selection revocation, disable and clean quit/restart retire the matching attempt and break only that phase's streak. Construction or warmup success cannot clear a first-real-request hold; every phase has its own streak. Consumption atomically publishes the saturated count, consumed attempt UUID and cleared pending record. Same-launch/read/render/repeated owner access cannot add counts; a failed commit publishes no in-memory count or permission.

## Consent and controls

Safe Start is reachable from the menu, the first-run flow and the Hub's Safe Start page before model setup. Its finite cached health is separate from historical model-loaded health. “Ready” means tracking/admission is available; native preparation readiness is separately owned by the resident instance. Rendering performs no journal, model or loaded-build reads. No health journal is exported by default.

Enable creates a new consent UUID and clean owned ledger **before** saving enabled plus that UUID. Schema2 is required for this expanded scope. Valid schema1 (at most eight entries and only construction/synthetic phases) is byte-preserved, including pending records: opening it consumes nothing. Earlier saved consent requires turning Safe Start off, saving, and explicitly enabling it again with a new UUID. Reset/Retry and an old true flag/UUID cannot create expanded consent; failed saves never imply protection. Passive experiment-only/mixed/net-zero saves do not enter mic/model/credential setup. Draft disable immediately revokes old preparation, retires under old consent, and retains the native owner until actual exit. Saving opt-out/new unguarded work waits for that exit. Re-enable uses new explicit consent and clean health; old grants, attempts, counts, audio, jobs and leases do not revive.

Admission unavailability (legacy consent, missing/invalid/unknown records) does not invent a failed-retirement debt. After actual exit, explicit off can save while preserving those bytes. If a known schema2 required terminal retirement failed, opt-out stays unsaved and tracking remains unavailable. After actual exit, repair storage and explicitly Reset the owned health state before saving opt-out. Reset stays reachable while the draft switch is off. Reset repairs that known debt while keeping draft opt-out revoked. A fresh owner cannot infer expanded consent from an unreadable quarantine; explicit bounded repair alone cannot create it. A failed settings save also remains visible; neither failure silently admits unprotected preparation.

- **Keep safe start:** keeps the hold and revokes Retry authority; no native work.
- **Retry preparation once:** token/selection/consent/metadata-bound preparation only, on the existing serial native-exit chain. It constructs if needed and performs one synthetic warmup if that instance is not prepared. It cannot bypass or clear a first-real-request hold. It does not enter general setup, open the mic, migrate credentials, call a provider, transcribe old audio, replay Undo/recovery, save history or paste. Start a new origin action afterward.
- **Reset recovery state:** after actual native exit, clears only the owned bounded health ledger. It can retire validated owned bounded corruption; unknown/unowned/oversize/symlink objects remain refused and preserved. Reset performs no preparation and removes no models, installed cache, downloads, settings, history or recordings. Persistence failure stays visible.

Unknown/custom selections, missing loaded-build metadata, unsupported revisions, capacity or ownership faults refuse visibly when enabled; they never silently enter untracked native preparation. While enabled, canceled-capture Undo may only borrow the **same exact-scope resident that completed both synthetic warmup and a real recognition request**, after repeat read-only verification and authorization. The retained-resident helper has the same prerequisite. Cold, warm-only, in-flight, refused, old-generation and expired-operation residents refuse immediately, with no writes, decode or wait. It never initializes, warms up, writes the guard ledger or audio/cache, or waits for a later Retry to revive its expired job. Other origin refusals retain their existing audio-stash, lease, retention and completion policies.

## Identity, privacy and storage

A separate stable key uses catalog ID/expected full SHA-256/expected bytes, observed file size/mtime/optional change-time/inode, loaded app/native linker LC_UUID, architecture, bounded native version, adapter/compute revision, primary batch resource role, and construction, explicit synthetic warmup or first-real-audio-request phase. Caller origin, language, hints, provider, audio, transcript, error, private path/path digest, process build-scope UUID, operation, instance, selection epoch and consent are not stable build keys. UUID ownership fields are separate. All origins share the same primary resource role.

The enabled-only production reader uses the main Mach-O header and `dladdr`'s image base for the imported Whisper initializer, with a bounded pure LC_UUID parser (64 KiB/1,024 commands, exact UUID/magic/bounds/architecture checks). No model/binary disk hashing is added. Expected pins plus file metadata are freshness evidence, **not current-byte attestation**; same-stat replacement is not detected. LC_UUID identifies linker output, not signed attestation, source commit, Metal shader/driver identity or GPU cause. Deliberately reused UUIDs are not detected. Real loaded-image availability and packaged Intel/arm64 behavior still need separate qualification; no loaded-image probe was executed here.

App storage is separate from installed models/downloads/cache: `~/Library/Application Support/Parla-preparation-health/v1`. The private owned directory and held descriptors are checked for owner/type/mode (0700); files are regular, owned, single-link, nofollow, mode 0600. A nonblocking process lock and one in-process transition owner serialize writes. Fixed bounded namespace: lock, health.json, one quarantine and one replacement; no sweep. Schema2 has at most 12 entries (schema1 validation remains at most eight old-phase entries), 16 KiB ledger/quarantine/temp, 512-byte key, 64 ASCII native-version bytes, counters saturated at two. Capacity refuses rather than silently evicting unresolved state.

Publication uses exclusive same-directory temp creation, complete bounded writes, file sync, atomic rename and directory sync, checking authority before rename. Failed publication never becomes a grant. Explicit reset retires only checked bounded owned state; unsupported sync/locking, unknown files, malformed data and ownership violations refuse. The owner reserves each storage transaction and releases its lock for IO; concurrent admission refuses. Owner → readiness is the only nested lock order. No readiness/owner lock is held across native execution, waits, IO or arbitrary predicates/callbacks. The single raw C pointer owner frees a returned context even when terminal persistence fails.

## First request and resident lifetime

Ordinary, command, stream head/tail, windowed final, HUD preview and timed file requests converge on the same envelope after existing skip/capability/abort checks. Minimum-duration/silence skips and confirmed-window assembly without a tail do not claim success. Adapter preflight failure can retire an attempted request as a returned failure without entering C; it cannot promote readiness. In the pinned concrete Whisper adapter a completed result implies the full call returned successfully, including empty text. This is not a claim about meaningful inference on short input or native hidden preparation.

Shared resident state atomically moves from unattempted to one in-flight attempt, then completed or refused. Successful later requests on that resident use fresh operation permits and perform no further guard writes. Failed/canceled/refused first attempts cannot repeatedly warm or retry that instance. A first stream failure therefore refuses later final recognition on that instance. Start a new deliberate acquisition/action; a two-UNKNOWN first-request hold requires Reset after actual exit, then a new origin. No old audio or Undo offer waits or revives. Preview and fresh final instances each have their own first attempt.

The returned native result remains separate from delivery authorization: a returned native success/failure survives terminal-persistence or late permission refusal, with text suppressed where delivery is refused. Phase abort/client revocation predicates are sampled outside owner/readiness locks immediately before entry and at finalization. Cancellation observed at finalization wins readiness; later cancellation suppresses delivery without rewriting the durable terminal. A separate recovery generation rotates on successful explicit Reset/new consent. New permits cannot re-stamp old residents after Reset. Keep/Retry revoke grants without gratuitously rotating that generation.

## Lifecycle and qualification limits

Enabled setup runs in one nonisolated async work body on the existing processTask barrier; construction and warmup do not append a nested/self-awaited chain. Cancellation revokes logically and retires immediately through a separate bounded operation observer without replacing child cancellation, while the barrier/client lives until native actually exits. Stale selection/consent/operation grants cannot promote or clear newer state. Native hangs may wait indefinitely; no timeout permits freeing them.

The concrete preparation termination participant closes admission, retires clean quit and waits the stable owned chain plus required journal retirement. It composes with existing clipboard/updater/download owners and the Undo termination wrapper, retaining their original/provider/failure holds and once-only reply. A prep persistence fault supplies its own finite quit-cancellation reason. This does not promise a new general graceful-quit drain for unrelated work. Restart reserves preparation before waiting; rejected claims and actual installer failure release only that reservation and retain independent quit closure. Canceled quit permits fresh deliberate work only.

Source tests use the real default factory and Whisper adapter with fake bottom native entry/decode, actual tiny private journals, injected build evidence and byte fixtures, and app acquisition/action/lifecycle seams. They allocate no real model/native context. A separately opt-in disposable fake-native host-death control can test a durable pending request and one fresh reader’s single UNKNOWN consumption; the externally forced owner exit is control evidence, not a passing XCTest or a native/GPU crash. These checks do not prove filesystem/power-loss durability, native scheduling/GPU behavior, model quality, field input, user benefit or deployment support. Force quit, device loss and arbitrary disk/power failures remain outside preservation guarantees. B19 standalone-build permission is unanswered; B24 field actions remain absent. B16's optional adapter and native/human qualification remain pending.
