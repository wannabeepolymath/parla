# Catalog model downloads

The Hub and status menu share one app-owned download/install owner for the three existing catalog models. Download starts an explicit action. Pause keeps completed chunks; Resume and Retry create a fresh action. Discard removes only proven-owned staging state after the writer exits. Paused downloads appear after relaunch without network activity, installation or model selection.

Staging lives in the private `models/downloads` directory, separate from installed filenames. Each bounded version-1 journal pins the catalog ID, canonical URL, expected size and full SHA revision, random staging name, generation, committed offset and a bounded validator. Unknown, linked, escaping, malformed or oversized state is refused and preserved. Directory enumeration stops at 16 entries; journals are at most 4 KiB. No directory sweeps delete orphan or unknown files.

Production requests use 8 MiB ranges and identity encoding. A resumed append requires the same strong ETag, or a strictly parsed Last-Modified date with no ETag and at least 60 seconds of server-reported age. Missing/weak validators cause one full restart; changed validators on a partial response fail visibly. Exact single ranges, total size and actual body length must match. A complete 200 response is a separately staged, size-bounded full replacement, never appended to a prefix. A valid unsatisfied-range response permits one restart; a complete local stage instead goes directly to verification. Redirects must remain HTTPS on Hugging Face/CDN domains, without URL credentials or an alternate port. Transient signed URLs, cookies, credentials and response bodies are not journaled or logged.

Chunks stream to disk, are validated before append, and synchronize before the journal advances atomically. Relaunch trusts only the committed offset and truncates only an owned uncommitted suffix on explicit resume. Short or missing committed data fails safely. The journal rename is serialized with Pause authority; a cancellation arriving during append or synchronization cannot advance the committed offset. Canceled chunks never commit. Rejected final bytes are reset for an explicit Retry. This is a bounded durable checkpoint policy, not a filesystem-wide power-loss guarantee.

Only complete pinned bytes enter the existing `ModelCatalog.install`: full size, markup and streaming SHA checks remain mandatory. Existing-model rename/rollback and cache-after-publication behavior are unchanged. A completed stage can retry installation without downloading. If publication consumed the stage before journal cleanup, explicit Retry re-verifies the installed file before resolving the journal. The installer's backup/move sequence retains its existing power-failure limitations; it is not a newly qualified crash transaction.

A fresh explicit action may select its installed model only while the user's selection epoch and authoritative settings choice remain current. Hub selection invalidates that intent immediately, including debounce and switch-away/back. A model draft predating the fresh Download intent may settle through debounce without revoking that newer action. Pending unrelated edits flush safely; invalid settings and save failures never authorize a fallback-default write or setup callback. Installation can finish without selecting the model. Pause/Discard and passive discovery do not request model setup.

Quit pauses and waits for the actual transport/install writer alongside the existing clipboard and updater owners. Canceling quit does not resume a download. Active work refuses updater restart; paused state permits restart, and a successful restart claim prevents a new download from racing it. The B57 shutdown wrapper remains in the real quit entry.

Network-free tiny-file tests exercise the production owner, actual URLSession disk adapter with URLProtocol, real verifier/installer/cache/settings and Hub/menu routes. Real CDN behavior, real disk exhaustion/interruption, process-kill/power-loss behavior and packaged native restart remain unqualified.
