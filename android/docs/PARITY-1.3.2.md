### Exact network request contracts to preserve

**Anthropic**: body is `{"model":"<id>","max_tokens":4096,"system":"<system>","messages":[{"role":"user","content":"<user>"}]}`; intentional transform uses 8192 output tokens. Mac optionally replaces `system` with one text block plus `cache_control:{"type":"ephemeral"}` only if its model-specific prompt-length gate passes; Android currently always sends a string. This is a cache optimization difference, not an authorization defect ([Cleanup.swift:413](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/Cleanup.swift:413), [Cleanup.swift:309](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/Cleanup.swift:309), [ApiClient.kt:35](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/ApiClient.kt:35)). Response text is concatenated `content` entries with type `text`; reject `max_tokens`, `model_context_window_exceeded`, `refusal` stop reasons. Mac also records response `model` and `usage.input_tokens`/`output_tokens` ([Cleanup.swift:471](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/Cleanup.swift:471), [ApiClient.kt:43](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/ApiClient.kt:43)).

**OpenAI-compatible**: body is `{"model":"<id>","max_completion_tokens":4096,"messages":[{"role":"system","content":"<system>"},{"role":"user","content":"<user>"}]}`. Neither client sets temperature, tools, streaming, `max_tokens`, organization or project headers. `Authorization: Bearer <key>` is absent for blank/keyless use. Read first choice `message.content` string or text-part array; reject `finish_reason` length/content_filter and nonempty refusal. Mac records response `model`, `usage.prompt_tokens`/`completion_tokens`; Android currently discards them ([OpenAICompatClient.swift:75](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/OpenAICompatClient.swift:75), [OpenAICompatClient.swift:113](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/OpenAICompatClient.swift:113), [ApiClient.kt:35](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/ApiClient.kt:35)).

**Reviewed failover transport**: Mac eligible failover reuses its bounded history transport: 16 KiB prompt, 128 KiB request, 256 KiB response, 16 KiB received/explicit outgoing headers, 1 MiB payload ledger. It does not discover models or use ambient cookies/cache/authentication retries. Copy those limits into the new chain, not Android’s existing 2 MiB primitive response allowance ([CleanupFactory.swift:217](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/CleanupFactory.swift:217), [HistoryRetryHTTP.swift:1](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/HistoryRetryHTTP.swift:1), [HistoryRetrySegmentation.swift:130](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/HistoryRetrySegmentation.swift:130)).

**Prompt payload**: ordinary user content is `<transcript>\n` + transcript. Transform user content is instruction + `\n\n<text>\n` + source selection/transcript. Untrusted source is never a system instruction. Ordinary cleanup includes vocabulary/snippets/style/app category/single-line rule; intentional transforms omit ordinary style/snippet/category additions ([Cleanup.swift:35](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/Cleanup.swift:35), [Cleanup.swift:184](/Users/daksh/mySpace/code/wisper/Sources/ParlaCore/Cleanup.swift:184), [PromptBuilder.kt:25](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/PromptBuilder.kt:25)).

### Check 4 — Microphone ownership, silence and capture hook

**Capture today**: new `WavRecorder` per explicit session; permission checked before creating `AudioRecord`; MIC input, 16,000 Hz, mono PCM16, at least twice minimum buffer or 4096 bytes. A coroutine reads nonblocking, writes a private WAV, emits RMS levels, caps at 300 seconds, and releases recorder in `finally` ([WavRecorder.kt:31](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:31), [WavRecorder.kt:52](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:52), [WavRecorder.kt:66](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:66), [WavRecorder.kt:113](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:113)). `ParlaService` owns capture through its job, then local recognition and text cleanup; it uses the same recorder cleanup on failure/cancel ([ParlaService.kt:121](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/ParlaService.kt:121), [ParlaService.kt:156](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/ParlaService.kt:156)).

**Exact error source**: `WavInput.parse` throws `Recording is too short or silent. Speak for at least half a second.` when speech admission is enabled and either samples <6400 (**0.4 seconds** at 16 kHz) or whole-file RMS <1e-4. The copy says half a second, but threshold is 0.4 seconds. This runs before native recognition. It does not detect another app holding the microphone ([LocalSpeech.kt:37](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/LocalSpeech.kt:37), [LocalSpeech.kt:86](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/LocalSpeech.kt:86)). Capture already separately handles uninitialized mic, failed recording start, read errors, and zero-byte audio ([WavRecorder.kt:56](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:56), [WavRecorder.kt:63](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:63), [WavRecorder.kt:73](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:73), [WavRecorder.kt:90](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:90)).

**Correct Android signal**: use own `AudioRecord.registerAudioRecordingCallback(executor, callback)` (API 29+) and `AudioRecord.getActiveRecordingConfiguration()`. The callback reports capture changes including framework silencing; inspect `AudioRecordingConfiguration.isClientSilenced()` (API 29+) for **this recorder**, matching `clientAudioSessionId` if handling a list. These APIs fit existing minSdk 33 ([build.gradle.kts:10](/Users/daksh/mySpace/code/wisper/android/app/build.gradle.kts:10)). Official references: [AudioRecord callback and active configuration](https://developer.android.com/reference/android/media/AudioRecord), [AudioRecordingConfiguration](https://developer.android.com/reference/android/media/AudioRecordingConfiguration).

`AudioManager.getActiveRecordingConfigurations()` / manager-level recording callback can provide supporting concurrent-session information, but the decisive state is whether Parla's own client is silenced. [Android's audio-input sharing rules](https://developer.android.com/media/platform/sharing-audio-input) allow policy-dependent concurrency; another active recorder does not automatically prove failure. Do not claim that these public APIs reliably identify the other app by package, or that every screen recorder monopolizes the microphone. A screen recorder configured for device audio alone is not evidence of mic contention. A non-silenced silent buffer still needs ordinary duration/RMS checks.

**Hook location**: in `WavRecorder.record`, register after successful `AudioRecord` construction and before `startRecording`; inspect active configuration after recording starts, then respond to callbacks throughout capture. Keep a recorder-session-owned finite `silenced` reason (thread-safe because callback/capture executors differ). On silencing, signal `ParlaService` through a typed callback/failure, stop the current recording and offer an actionable retry after the conflicting recording ends. Unregister in the same `finally` before release; cancellation must prevent a late callback from changing a newer session. Preserve source ownership and avoid retaining rejected silent PCM as a successful recording ([WavRecorder.kt:45](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:45), [WavRecorder.kt:92](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/WavRecorder.kt:92), [ParlaService.kt:129](/Users/daksh/mySpace/code/wisper/android/app/src/main/java/dev/parla/android/ParlaService.kt:129)).

Acceptance should distinguish: permission revoked, MIC start/read failure, framework-silenced own session, short audio, genuinely quiet audio, and no recognized speech. Test callbacks/configuration transitions with mocks first; physical contention tests remain necessary before claiming device support.
