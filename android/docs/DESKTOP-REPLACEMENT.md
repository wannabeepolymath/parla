# Desktop core replacement — implementation / review handoff

Authoritative sources were the current, dirty desktop `Pipeline`, `Cleanup` / `PromptBuilder` / `CleanupSanitizer`, `TextRules`, `Eval`, `Vocabulary`, `Profiles`, `Transforms`, `PendingOperation`, `History`, `HistoryRetry`, `Transcriber`, `ModelCatalog` and settings. This implementation did not edit desktop production files; unrelated dirty/concurrent workspace changes are preserved. Pre-rewrite source is preserved in `android/evidence/desktop-replacement/baseline-source.zip` and its original manifest. Historical APKs/evidence have not been relabeled or rebuilt.

## Wired product paths

- `Models.kt` is schema-3 policy: cleanup/raw/selectedPreset; standard/conversational/formal; local catalog selection; text-count history; explicit presets/replacements and exact-app profiles. Existing dictionary, snippets, history IDs/times/text and bubble settings migrate from schema 1. Schema 1/2 installations migrate with retained recovery audio **off** until explicit opt-in; new-install defaults are enabled / seven days, with setup/privacy disclosure. Old cloud transcription and category-style fields are deliberately discarded. Legacy installs inherit at least their existing row count (up to 1000), while new installs default to 50. Migration becomes durable on the next successful atomic write.
- `TextRules`, `PromptBuilder`, `Pipeline` port the actual desktop prompt and local policy. Whole-utterance matching uses conservative Eval-style English number/currency/ordinal folding, Unicode-aware tokens, deterministic longest-trigger ties and locally locked expansions. Vocabulary preserves saved priority with 256-byte per-hint / 2048-byte ASR / 8192-byte cleanup UTF-8 budgets. Literal rules are exact, case-sensitive, longest-first, non-cascading and treat Unicode marks/connectors as word constituents. Inline snippets remain provider prompt data, matching current desktop; they are not pre-expanded and then rewritten as ordinary source. Locked whole utterances bypass both provider and rules.
- `LocalSpeech` / `WavInput` validate bounded RIFF chunks, PCM16 mono little-endian 16kHz, signed /32768 conversion, max300s, minimum6400 samples and RMS1e-4. Non-speech marker stripping follows desktop. `SpeechLanguages` copies the pinned upstream language catalog. English models force English. Multilingual pinned languages remain pinned; auto uses the last language (initially English), then a SOT logits language check and one re-decode if needed, following desktop policy. Greedy decoding retains native temperature fallback and audio context defaults.
- `native/` vendors 142 unmodified required upstream files from exact v1.9.1 revision and hash, including ggml and notices. Static CPU dependencies feed `libparla-whisper.so`; ABIs are arm64-v8a/x86_64. No GPU/OpenMP/native-host instruction flags. r27b flexible pages and 16KiB link option are configured. Source can be reproduced with the hash-verifying bootstrap; no runtime source dependency exists.
- `NativeTasks` is a process-owned serial executor used by inference, verification/selection, atomic install and deletion. JNI token IDs are validated through a shared-ownership registry; no raw context pointer crosses JNI. Cancellation is immediate via a separate atomic-token call, not queued behind decode. Native init cannot abort, so delivery is revoked and init/decode still drain before context destruction or another native/model operation. PCM, strings and callbacks live until actual native exit. Abort never calls JNI. Speech uses standard UTF-8 byte arrays, preserving emoji/Indic text across JVM UTF-16. All JNI entrypoints contain C++ exceptions. Contexts unload after each call instead of desktop's default five-minute idle reuse.
- `ModelManager` / `TransferStorage` persist private partial bytes and atomic checkpoints with catalog ID/URL/size/SHA, committed offset, strong validator and generation. Download / Pause / Resume / Discard are explicit. Process-death discovery reads bounded metadata and projects paused state without network/hash/install/selection. Only synchronized complete chunks advance the journal; uncommitted tails truncate on Resume. Requests use bounded Range and validated If-Range; exact Content-Range/total and matching validators gate 206; a complete 200 safely restarts staging; valid empty 416 permits one bounded whole-file retry. Missing/weak validators require a whole-file restart. Whole size/SHA/markup validation is mandatory before atomic install on the native serial executor. Pause/discard/restart wait for actual writer/native completion, including cancellation before coroutine dispatch; stale generations cannot publish a journal or UI update. Failed/canceled transfers preserve the installed file and selection. Selection is explicit and never falls back silently. The injectable production manager uses a separate fresh unauthenticated HTTPS transport, including a credential-free allowlisted HTTPS redirect chain. Unknown/unsafe/corrupt provenance is preserved with an error rather than silently deleted.
- `DictationFlow` is the session policy exercised by unit integration tests and called from the real service. Settings/profile resolve before capture; stages progress through local recognition, cleanup, ready and one guarded delivery. Result retention/persistence precedes insertion. The authorization callback marks and persists an uncertain-write outcome immediately before the actual editor API, and cancel during verification keeps original/result and says insertion may have occurred. Existing original-node/selection/text/generation, sensitive/private editor and one-use lease guards remain. No automatic clipboard fallback/replay is present.
- Dictionary preserves saved priority through editing and explicit Move up / Move down. The 256-byte per-hint / 2048-byte ASR / 8192-byte cleanup budgets are disclosed; profile vocabulary still prepends in saved order.
- `RecoveryVault` holds one original/result and outcome in process RAM, with a 5-minute expiry and combined64KiB cap. The Home card shows uncertainty plus original/result/copy/dismiss controls even when history is suppressed or saving fails. Clipboard writes are explicit and retain the existing sensitive-clipboard flag. No result text is placed in notification/status messages. Over-limit results cannot be retained in this transient slot; the visible completion note names that limit.
- `LocalState` is the actual production durable-write/load-error gate with injectable atomic storage in tests; `Store` supplies Android `AtomicFile` and existing `AndroidKeyStore` identity. Publish follows successful write. Malformed/unreadable state blocks all writes and provider credential access until successful reload or explicit repair. Repair preserves exact original bytes in a dated private `parla-data.pre-repair-*.json` before saving. Credential ciphertext v2 includes canonical provider/endpoint scope; v1 is readable only for an explicit user Save/rebind, not ordinary provider work. Package, filenames, keystore alias and backup exclusions are unchanged.
- `HistoryRetry` freezes raw/current global settings with unknown destination, uses no ASR/insertion, has per-row request tokens and source-version checks, and shows a proposed result for explicit save/copy. Failure leaves prior cleaned text unchanged. New requests/deletion/clear invalidate stale proposals; update-only application cannot resurrect deleted rows. Original access and share/export (plain text/Markdown via Android document picker) are wired.
- Compose keeps the existing shell/assets. Models, modes, styles, cleanup toggle, presets, replacements, profile CRUD/enable, history count, non-destructive history disable, clear, repair/reload and optional provider configuration are wired. Missing global/profile model routes to Models, never key setup. Gboard stays selected.

## Deliberate platform scope / remaining qualifications

`RecordingStore` and the service-used `CaptureRecovery` retain complete failed-recognition/interrupted audio under a separately configurable policy: enabled / seven days for new installs, 1–30 days, private `noBackupFilesDir/recordings`, at most 300 seconds per PCM16 mono 16kHz WAV, and 128MiB / 128 files total including unfinished/unknown leaves for admission. This Android total quota is additional to desktop’s 128MiB per-recording cap; Android’s capture-duration bound is tighter. Schema 1/2 migrations remain off until explicit opt-in, a privacy-preserving difference from desktop’s default. Turning retention off stops new stashes without silently deleting old recovery files. Text-history-off independently suppresses automatic text writes.

Stash validates complete bounded WAV bytes, writes/synchronizes a private dated partial, then atomically publishes before ASR. Failed writes are not offered as viable recordings. For ordinary dictation, raw recognition success controls disposal even if cleanup/insertion later fails. Failed recognition retains audio; canceled/private sessions do not become recovery candidates. Cancellation marks a capture for durable purge and actual reader exit performs disposal. A crash leaves dated partials unavailable but deletable/expirable; completed failed WAVs become available after restart. Policy/load/write errors never authorize a new stash or retranscription from fallback settings. Symlink/hardlink/directory aliases, unexpected names, source-identity changes, corrupt/oversized WAV and storage/quota failures are refused. Active capture/ASR/playback leases block deletion/pruning/clear; revocation alone never pretends the native reader has exited. Cache cleanup excludes process-owned active files across service recreation.

The functional Recovery audio screen lists date/duration/size/expiry and reasons for unavailable/busy rows. Explicit local Play/Stop uses a short-lived player and exclusive lease; leaving/backgrounding the screen releases playback. Retranscribe freezes current valid **global** model/language/vocabulary, reauthorizes current settings and source identity at queued native use, and runs the existing serial local engine with no provider, cleanup or editor insertion. It holds original text in the screen preview. Retranscription always preserves the retained source until explicit Delete/Clear or retention expiry, including after success, Save, cancellation, navigation or activity recreation. This deliberate Android difference avoids losing both the source and a screen-owned preview while navigating to enable history. Returning users can retranscribe again. Canceled native work retains ownership through actual exit. Copy is explicit; Save is update-gated and requires history on, disclosing the current row-count retention limit. Delete/Clear/expiry report busy/failed actions instead of racing readers. No device playback or real model decode has been qualified.

Site/URL profiles are unavailable without trusted Android URL metadata. No screen scraping or arbitrary editor context reaches providers. macOS-only hotkeys, selected-desktop-text/spoken-command transforms, automation, Apple Intelligence, desktop diagnostics/cost accounting and desktop warm/streaming preview integrations are not implemented or represented by placeholder controls. Saved presets do transform dictated raw text and historical originals. Exact app profiles inherit global output mode/provider; there is no automatic provider switch per app.

OpenAI-compatible endpoints require an explicit model and production HTTPS; desktop server-model discovery and HTTP loopback operation are absent. Anthropic prompt-cache billing hints and provider usage/cost history are not ported. Length guards/tie ordering use extended graphemes, and literal rules/snippet matching/vocabulary deduplication preserve canonical Unicode equivalence. Shared Swift/Kotlin fixtures cover NFD accents, family/flag/skin-tone emoji and CRLF. Platform runtime Unicode versions may still differ at newly added grapheme boundaries; this is not a code-point approximation.

No actual model was downloaded, initialized or decoded. No device/emulator/browser, microphone, Accessibility write, Compose interaction, Android keystore migration, real provider, APK packaging, linked native library or ELF page alignment was exercised. Native compilation checks cover source syntax for both generated NDK target configurations, not linking or runtime ABI/device compatibility. Device memory/speed/accuracy remain unqualified. No new APK is claimed; historical1.2.0 artifacts remain historical. Root ran both shared Swift tests, including the complete prompt contract, with no failures.

## Verification and resources

Focused JVM tests exercise production `Pipeline`, `DictationFlow`, `LocalSpeech` with injected native seam, `LocalState`, model copy/verification/install policy, history ownership and retained insertion guards. Two versioned fixtures, `fixtures/desktop-android-v1.json` and `fixtures/desktop-prompts-v1.json`, are consumed by Kotlin `ProductCoreTest` and Swift `AndroidSharedPolicyTests` (test-only desktop edit). The latter checks five complete system/user prompt pairs generated from actual desktop production symbols: ordinary, email, terminal/single-line, conversational and intentional transform. Canonical-equivalent inline snippet allowance is also exercised through the real provider pipeline with mock responses.

Final root results and the disposition of both independent-review findings are in `android/evidence/desktop-replacement/ROOT-FINAL-CHECKS.json` and `ROOT-REVIEW.md` in the same evidence directory. Earlier portable-continuation commands/results, regression evidence and resource inventory are in `android/evidence/desktop-replacement/PORTABLE-IMPLEMENTATION-RESULTS.md`; `IMPLEMENTATION-RESULTS.md` and old logs remain historical evidence. No model/account/key/live-provider/paid calls, global tooling/dependency upgrades, commits/push/publish, device sessions or servers were created. Gradle outputs and CMake metadata remain task-generated in the ignored `android/app/build` and `android/app/.cxx`; compatible shared caches are preserved. The source archive acquired for vendoring was removed after hash verification/extraction. The vendored source, bootstrap, manifest and checks are intentional repository resources.
